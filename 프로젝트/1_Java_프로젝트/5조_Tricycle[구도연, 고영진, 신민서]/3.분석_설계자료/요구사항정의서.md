## 1. 프로젝트 개요

| 항목 | 내용 |
| :--- | :--- |
| 프로젝트 목적 | 콘솔 기반 카페 키오스크 시스템을 구현하여 회원/비회원 주문과 관리자 운영 기능을 제공한다. |
| 대상 사용자 | 비회원, 회원, 관리자 |
| 개발 환경 | Java 18, MySQL 8.0, JDBC, UTF-8 |
| 시스템 범위 | 회원가입/로그인, 상품 주문, 포인트 관리, 관리자 운영 관리, 매출 통계 조회 |
| 운영 방식 | 콘솔 메뉴 선택 기반 상호작용 |

## 2. 사용자 및 역할 정의

| 역할 | 설명 | 주요 목표 | 주요 사용 기능 |
| :--- | :--- | :--- | :--- |
| 비회원 | 회원가입 없이 주문만 가능한 사용자 | 빠른 상품 주문 | 메뉴 조회, 옵션 선택, 장바구니 관리, 주문 완료 |
| 회원 | 로그인 후 추가 혜택을 이용하는 사용자 | 주문 이력 관리, 포인트 활용, 맞춤 주문 | 회원가입, 로그인, 주문, 퀵오더, 추천 메뉴, 포인트 조회, 선호 카테고리 관리 |
| 관리자 | 매장 운영과 데이터 관리를 담당하는 사용자 | 상품/회원/주문/통계 운영 | 관리자 인증, 카테고리 관리, 메뉴 관리, 옵션 관리, 회원 관리, 주문 관리, 통계 조회 |

## 3. 기능 요구사항

| 요구사항 ID | 구분 | 기능명 | 상세 요구사항 | 우선순위 | 비고 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| FR-01 | 공통 | 메인 메뉴 진입 | 시스템은 시작 시 회원, 비회원 주문, 관리자 모드, 종료 메뉴를 제공해야 한다. | 필수 | `StartView`, `MenuView` |
| FR-02 | 회원 | 회원가입 | 사용자는 전화번호, 비밀번호, 나이, 선호 카테고리를 입력하여 회원가입할 수 있어야 한다. | 필수 | 전화번호 중복 불가 |
| FR-03 | 회원 | 가입 축하 포인트 | 시스템은 회원가입 완료 시 1,000포인트를 자동 적립해야 한다. | 필수 | 포인트 이력 저장 포함 |
| FR-04 | 회원 | 로그인 | 사용자는 전화번호와 비밀번호로 로그인할 수 있어야 한다. | 필수 | 인증 실패 시 안내 메시지 출력 |
| FR-05 | 회원 | 주문 내역 조회 | 회원은 자신의 과거 주문 내역과 주문 상세 옵션 정보를 조회할 수 있어야 한다. | 중요 | 완료/취소 상태 포함 |
| FR-06 | 회원 | 퀵오더 | 회원은 최근 주문 1건을 불러와 동일 주문을 빠르게 재주문할 수 있어야 한다. | 중요 | 장바구니 초기값으로 사용 |
| FR-07 | 회원 | 추천 메뉴 조회 | 회원은 선호 카테고리를 기반으로 추천 메뉴를 조회할 수 있어야 한다. | 중요 | 선호 카테고리 설정 필요 |
| FR-08 | 회원 | 선호 카테고리 변경 | 회원은 자신의 선호 카테고리를 변경할 수 있어야 한다. | 중요 | 추천 메뉴 기준 데이터 |
| FR-09 | 회원 | 포인트 내역 조회 | 회원은 포인트 적립/차감 내역과 사유를 조회할 수 있어야 한다. | 중요 | `POINT_HISTORY` |
| FR-10 | 주문 | 비회원 주문 | 비회원은 로그인 없이 상품 주문 절차를 진행할 수 있어야 한다. | 필수 | 포인트 사용 불가 |
| FR-11 | 주문 | 메뉴 탐색 | 사용자는 인기 상품, 신상품, 카테고리별 메뉴, 추천 메뉴를 기준으로 메뉴를 조회할 수 있어야 한다. | 필수 | 추천 메뉴는 회원 기준 기능 |
| FR-12 | 주문 | 옵션 선택 | 사용자는 선택한 메뉴에 대해 옵션 그룹과 세부 옵션을 선택할 수 있어야 한다. | 필수 | 메뉴별/카테고리별 옵션 지원 |
| FR-13 | 주문 | 수량 선택 | 사용자는 메뉴 수량을 입력하여 장바구니에 담을 수 있어야 한다. | 필수 | 1개 이상 입력 |
| FR-14 | 주문 | 장바구니 관리 | 사용자는 장바구니에서 상품 삭제, 수량 변경, 전체 비우기를 수행할 수 있어야 한다. | 필수 | 주문 전 반복 수정 가능 |
| FR-15 | 주문 | 주문 확정 | 사용자는 장바구니 확인 후 주문 여부를 최종 확정할 수 있어야 한다. | 필수 | 빈 장바구니 주문 불가 |
| FR-16 | 주문 | 포인트 사용 | 회원은 주문 시 보유 포인트 범위 내에서 포인트를 사용할 수 있어야 한다. | 필수 | 비회원은 사용 불가 |
| FR-17 | 주문 | 포인트 적립 | 시스템은 회원 주문 완료 시 결제 금액 기준으로 포인트를 적립해야 한다. | 필수 | `(결제금액) / 10` 기준 |
| FR-18 | 주문 | 주문 저장 | 시스템은 주문, 주문 상세, 선택 옵션, 사용 포인트, 적립 포인트를 저장해야 한다. | 필수 | 주문 스냅샷 보존 |
| FR-19 | 관리자 | 관리자 인증 | 시스템은 관리자 전화번호와 비밀번호를 통해 관리자 인증을 수행해야 한다. | 필수 | 일반 회원은 관리자 메뉴 접근 불가 |
| FR-20 | 관리자 | 카테고리 관리 | 관리자는 카테고리를 등록, 조회, 삭제할 수 있어야 한다. | 필수 | 중복명 방지 필요 |
| FR-21 | 관리자 | 메뉴 관리 | 관리자는 메뉴를 등록, 조회, 수정, 삭제할 수 있어야 한다. | 필수 | 가격, 설명, 판매 상태 포함 |
| FR-22 | 관리자 | 옵션 그룹 관리 | 관리자는 옵션 그룹을 등록, 조회, 삭제할 수 있어야 한다. | 필수 | 예: 온도, 사이즈 |
| FR-23 | 관리자 | 세부 옵션 관리 | 관리자는 옵션 그룹별 세부 옵션을 등록, 수정, 삭제할 수 있어야 한다. | 필수 | 예: HOT, ICE, Large |
| FR-24 | 관리자 | 메뉴-옵션 매핑 | 관리자는 메뉴별 전용 옵션 그룹을 연결 또는 해제할 수 있어야 한다. | 중요 | 메뉴별 예외 처리 지원 |
| FR-25 | 관리자 | 회원 조회 및 관리 | 관리자는 회원 목록을 조회하고, 회원 삭제, 포인트 수정, 역할 변경을 수행할 수 있어야 한다. | 필수 | 관리자 보호 정책 적용 |
| FR-26 | 관리자 | 주문 관리 | 관리자는 전체 주문 목록을 조회하고 주문 취소를 수행할 수 있어야 한다. | 필수 | 취소 시 상태 변경 |
| FR-27 | 관리자 | 매출 통계 조회 | 관리자는 날짜별, 카테고리별, 메뉴별, 기간별, 시간대별, 요일별, 우수 회원 통계를 조회할 수 있어야 한다. | 중요 | 콘솔 리포트 출력 |
| FR-28 | 관리자 | 통계 파일 출력 | 관리자는 매출 통계를 CSV 파일로 저장할 수 있어야 한다. | 중요 | 보고서 파일 생성 |
| FR-29 | 정책 | 1인 관리자 정책 | 시스템에는 관리자 권한을 가진 회원이 1명만 존재해야 한다. | 필수 | 역할 변경 시 검증 |
| FR-30 | 정책 | 관리자 보호 정책 | 관리자 계정은 직접 삭제할 수 없고 포인트 수정 대상이 될 수 없어야 한다. | 필수 | 운영 안전 장치 |

## 4. 데이터 요구사항

| 데이터 ID | 데이터명 | 설명 | 주요 속성 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| DR-01 | MEMBER | 회원 기본 정보 및 권한 정보 | 회원번호, 전화번호, 비밀번호, 나이, 포인트, 역할, 선호 카테고리, 가입일 | 전화번호 식별 |
| DR-02 | CATEGORY | 메뉴 분류 정보 | 카테고리 ID, 카테고리명 | 커피, 논커피, 디저트 등 |
| DR-03 | MENU | 판매 메뉴 정보 | 메뉴 ID, 카테고리 ID, 메뉴명, 가격, 설명, 판매 여부, 등록일 | 품절 처리 가능 |
| DR-04 | OPTION_GROUP | 옵션 그룹 정보 | 그룹 ID, 그룹명 | 온도, 사이즈 등 |
| DR-05 | MENU_OPTION | 옵션 상세 정보 | 옵션 ID, 그룹 ID, 옵션명, 추가 금액, 표시 순서 | 그룹별 다건 보유 |
| DR-06 | MENU_OPTION_GROUP | 메뉴별 옵션 매핑 정보 | 메뉴 ID, 그룹 ID, 표시 순서 | 메뉴 전용 옵션 연결 |
| DR-07 | ORDERS | 주문 헤더 정보 | 주문 ID, 회원 ID, 총액, 사용 포인트, 적립 포인트, 상태, 주문일시 | 비회원 주문 시 회원 ID는 NULL |
| DR-08 | ORDER_ITEM | 주문 상세 정보 | 주문상세 ID, 주문 ID, 메뉴 ID, 수량, 단가, 메뉴명 스냅샷, 카테고리명 스냅샷 | 과거 주문 보존 목적 |
| DR-09 | ORDER_ITEM_OPTION | 주문 상세 옵션 정보 | 주문상세 ID, 옵션 ID | 주문 시점 선택 옵션 |
| DR-10 | POINT_HISTORY | 포인트 변동 이력 | 이력 ID, 회원 ID, 변동 금액, 사유, 생성일시 | 적립/차감 이력 관리 |
| DR-11 | WISHLIST | 회원 찜 정보 | 찜 ID, 회원 ID, 메뉴 ID, 생성일시 | 현재 UI 범위에서는 미노출 |

## 5. 비기능 요구사항

| NFR-06 | 이력 추적 | 포인트 변동과 주문 상세 옵션은 이력 데이터로 보존되어야 한다. | 중요 | 감사 추적성 확보 |
| NFR-07 | 인코딩 호환성 | 콘솔 출력과 소스 파일은 UTF-8 환경에서 정상 동작해야 한다. | 중요 | 한글 깨짐 방지 |
| NFR-08 | 보고서 활용성 | CSV 파일은 외부 문서 도구에서 활용 가능한 형식으로 저장되어야 한다. | 중요 | 관리자 보고용 |
| NFR-09 | 유지보수성 | MVC 및 계층 분리를 유지하여 기능 변경 시 영향 범위를 줄여야 한다. | 중요 | 현재 구조 기준 |
| NFR-10 | 환경 의존성 | 시스템은 MySQL 연결 정보가 외부 설정 파일로 관리되어야 한다. | 중요 | `dbinfo.properties` |

## 6. 업무 규칙 및 제약사항

| 구분 | 내용 |
| :--- | :--- |
| 주문 규칙 | 비회원도 주문 가능하나 포인트 사용 및 회원 전용 기능은 사용할 수 없다. |
| 포인트 규칙 | 포인트는 보유 포인트 이하, 주문 금액 이하로만 사용 가능하다. |
| 적립 규칙 | 주문 적립 포인트는 실결제 금액 기준 10% 수준의 정수 계산으로 반영한다. |
| 관리자 규칙 | 관리자 권한은 1명만 허용되며, 관리자 계정은 직접 삭제 및 포인트 수정이 불가하다. |
| 메뉴 규칙 | 메뉴는 판매 가능 여부를 관리할 수 있어야 하며, 옵션 그룹은 메뉴별로 개별 매핑 가능해야 한다. |
| 데이터 규칙 | 주문 상세에는 메뉴명과 카테고리명을 스냅샷으로 저장하여 이후 원본 메뉴 변경 시에도 과거 주문을 유지해야 한다. |
| 운영 제약 | 콘솔 기반 시스템이므로 실제 카드 결제, 영수증 프린터, 모바일 연동은 범위에서 제외한다. |
| 구현 범위 메모 | `WISHLIST` 관련 저장소와 서비스는 존재하지만 현재 메인 사용자 화면 범위에는 포함하지 않는다. |
