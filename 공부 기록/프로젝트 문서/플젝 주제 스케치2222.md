## 🏛️ 서비스 컨셉: "룸디코더 (Room Decoder)"
> **연결 키워드:** 7. 프라이스 디코딩(권리분석) + 3. 제로클릭(서류 자동인식) + 1. 휴먼 인 더 루프(체크리스트 체크)

어렵고 위험한 부동산 계약 전 과정을 AI가 동행하며 위험 요소를 '해독(Decoding)'하고 나만의 맞춤형 체크리스트를 만들어주는 풀스택 서비스입니다.

## 💻 시스템 아키텍처 및 데이터 흐름 (Data Flow)
이 프로젝트의 핵심 기술 챌린지는 "유저가 업로드한 PDF/이미지 서류를 어떻게 AI에게 안전하고 정확하게 전달하여 분석할 것인가"입니다.

```text
[유저: 등기부 PDF 업로드] ──> [Next.js (프론트)] ──> [S3 업로드]
														│
														▼
[AI 분석 결과 화면] <── [FastAPI / Spring Boot] <── [Upstage OCR 또는 CLOVA OCR]
								│ (텍스트 추출)
								▼
						[OpenAI GPT-4o] ── (위험 조항 분석) ──> [PostgreSQL 저장]
```

### 🛠️ 백엔드 핵심 기술 스택 추천
- **Main API 서버:** **FastAPI (Python)** 또는 **Spring Boot**
    - _추천:_ PDF/이미지 처리와 AI(LLM) 파이프라인 연동이 많으므로 **FastAPI**가 생산성 면에서 유리할 수 있습니다. 다만 익숙한 프레임워크를 선택하셔도 무방합니다.
    
- **OCR 엔진:** 유저가 올린 등기부등본 PDF나 사진에서 텍스트를 추출하기 위해 **Upstage Document OCR API**나 **Naver CLOVA OCR**을 연동합니다. (이 경험 자체가 포트폴리오에서 엄청난 가산점입니다.)

## 🎯 핵심 기능별 구현 방향 및 스케치

### 1. AI 부동산 서류 디코더 (핵심 기능)
- **기능:** 유저가 등기사항전부증명서(등기부등본)나 건축물대장을 올리면, AI가 갑구(소유권, 가압류 여부)와 을구(근저당권, 융자 여부)를 분석해 줍니다.
    
- **AI 에이전트의 역할:** "까다로운 공인중개사 친구"
    - _텍스트 예시:_ "도연님, 이 집의 을구를 보니 근저당권(대출)이 집값의 70%나 잡혀있어요. 전세로 들어가기엔 깡통전세 위험이 높은 '빨간불' 상태입니다!"
    
- **개발 포인트:** OCR로 추출된 텍스트 중 근저당권설정, 압류, 신탁 같은 핵심 키워드를 AI 프롬프트에 주입(Prompt Injection)하여 위험 점수(Green/Yellow/Red)를 계산하도록 로직을 설계합니다.

### 2. 하이브리드 체크리스트 (휴먼 인 더 루프)
- **기능:** 서류 분석 결과(전/월세 구조)와 집의 형태(아파트/원룸)에 따라 **반드시 확인해야 할 체크리스트를 동적으로 생성**해 줍니다.
    
- **구현 방법:**
    - **공공데이터 활용:** 국토교통부나 서울시에서 제공하는 **'전세사기 예방 체크리스트' 가이드라인 및 표준임대차계약서 양식 데이터**를 DB에 기초 데이터로 적재합니다.
        
    - **유저 참여:** 유저가 매물을 보러 가서 앱을 켜고 "수압 정상인가요?", "계약서 특약사항에 이 조항이 있나요?" 등을 체크하면, 최종적으로 "이 계약 진행해도 안전합니다"라는 종합 보고서를 도출합니다.

### 3. 층간소음 및 주거 환경 데이터 매핑 (데이터 크롤링/API)
- **기능:** 계약하려는 건물의 과거 민원이나 불편 사항 정보를 미리 체크합니다.
    
- **현실적인 데이터 수집 방향:**
    - 실제 빌라나 원룸 개별 호수의 실시간 층간소음 민원 데이터는 공공 API로 제공되지 않는 경우가 많습니다.
    
    - **대안 (포트폴리오용 우회 전략):**
		- 공동주택관리 정보시스템(K-APT) 데이터를 활용해 해당 아파트/단지 전체의 관리비 대비 소음/주거 민원 만족도 지표를 가져오거나,
		- 앱 내에 '이 집 살았던 사람들의 한줄평 리뷰 및 민원 공유 공간(커뮤니티)'을 구축하여 유저들이 직접 층간소음 점수를 매기도록 유도하는 구조가 훨씬 현실적이고 구현하기 좋습니다.

## 🗄️ 데이터베이스 테이블 구조 (ERD 스케치)

```sql
-- 1. 매물 정보 테이블
CREATE TABLE properties (
    property_id SERIAL PRIMARY KEY,
    address VARCHAR(255) NOT NULL,
    building_type VARCHAR(50), -- 아파트, 원룸, 오피스텔
    contract_type VARCHAR(20), -- 전세, 월세
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. AI 서류 분석 결과 테이블
CREATE TABLE document_analyses (
    analysis_id SERIAL PRIMARY KEY,
    property_id INT REFERENCES properties(property_id),
    document_type VARCHAR(50), -- 등기부등본, 건축물대장
    raw_ocr_text TEXT,
    risk_level VARCHAR(10),     -- SAFE, WARNING, DANGER
    ai_report TEXT,             -- AI가 쉽게 풀어쓴 해독 리포트
    analyzed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 3. 현장 실사 체크리스트 테이블 (휴먼 인 더 루프)
CREATE TABLE checklists (
    checklist_id SERIAL PRIMARY KEY,
    property_id INT REFERENCES properties(property_id),
    water_pressure BOOLEAN,     -- 수압 체크
    mold_status BOOLEAN,         -- 곰팡이 여부
    noise_complaints_count INT DEFAULT 0, -- 유저 제보 기반 층간소음 수
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
