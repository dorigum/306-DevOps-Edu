# 🏛️ 서비스 컨셉: "룸디코더 (Room Decoder)"

> **연결 키워드:** ==프라이스 디코딩(권리분석) + 제로클릭(서류 자동인식) + 휴먼 인 더 루프(체크리스트 체크)==

어렵고 위험한 부동산 계약 전 과정을 AI가 동행하며 위험 요소를 '해독(Decoding)'하고 나만의 맞춤형 체크리스트를 만들어주는 풀스택 서비스입니다.

# 🎯 핵심 기능별 구현 방향 및 스케치
## 1. AI 부동산 서류 디코더 (핵심 기능)

- **기능:** 유저가 등기사항전부증명서(등기부등본)나 건축물대장을 올리면, AI가 갑구(소유권, 가압류 여부)와 을구(근저당권, 융자 여부)를 분석해 줍니다.
    
- **AI 에이전트의 역할:** "까다로운 공인중개사 친구"
    - _텍스트 예시:_ "도연님, 이 집의 을구를 보니 근저당권(대출)이 집값의 70%나 잡혀있어요. 전세로 들어가기엔 깡통전세 위험이 높은 '빨간불' 상태입니다!"
    
- **개발 포인트:** OCR로 추출된 텍스트 중 근저당권설정, 압류, 신탁 같은 핵심 키워드를 AI 프롬프트에 주입(Prompt Injection)하여 위험 점수(Green/Yellow/Red)를 계산하도록 로직을 설계합니다.

## 2. 하이브리드 체크리스트 (휴먼 인 더 루프)

- **기능:** 서류 분석 결과(전/월세 구조)와 집의 형태(아파트/원룸)에 따라 **반드시 확인해야 할 체크리스트를 동적으로 생성**해 줍니다.
    
- **구현 방법:**
    - **공공데이터 활용:** 국토교통부나 서울시에서 제공하는 **'전세사기 예방 체크리스트' 가이드라인 및 표준임대차계약서 양식 데이터**를 DB에 기초 데이터로 적재합니다.
        
    - **유저 참여:** 유저가 매물을 보러 가서 앱을 켜고 "수압 정상인가요?", "계약서 특약사항에 이 조항이 있나요?" 등을 체크하면, 최종적으로 "이 계약 진행해도 안전합니다"라는 종합 보고서를 도출합니다.

## 3. 층간소음 및 주거 환경 데이터 매핑 (데이터 크롤링/API)

- **기능:** 계약하려는 건물의 과거 민원이나 불편 사항 정보를 미리 체크합니다.
    
- **현실적인 데이터 수집 방향:**
    - 실제 빌라나 원룸 개별 호수의 실시간 층간소음 민원 데이터는 공공 API로 제공되지 않는 경우가 많습니다.
    
    - **대안 (포트폴리오용 우회 전략):**
		- 공동주택관리 정보시스템(K-APT) 데이터를 활용해 해당 아파트/단지 전체의 관리비 대비 소음/주거 민원 만족도 지표를 가져오거나,
		- 앱 내에 '이 집 살았던 사람들의 한줄평 리뷰 및 민원 공유 공간(커뮤니티)'을 구축하여 유저들이 직접 층간소음 점수를 매기도록 유도하는 구조가 훨씬 현실적이고 구현하기 좋습니다.

## 📖 4.임차인을 위해 '구체적이고 풍부하게' 채워 넣을 핵심 정보 콘텐츠

6가지 기능에 들어갈 텍스트와 가이드를 훨씬 날카롭고 실용적으로 채워 넣을 수 있는 구체적인 가이드라인입니다.

### ① 부동산 용어 요약 ➔ "ZIPT의 3초 번역기"

딱딱한 법률 사전을 긁어오는 게 아니라, 사회초년생의 언어로 번역해 줍니다.
- **근저당권설정:** ➔ "이 집을 담보로 집주인이 은행에서 빌린 돈입니다. 집주인이 돈을 못 갚으면 집이 경매에 넘어가 내 보증금이 위험해질 수 있어요."
    
- **대항력:** ➔ "내 보증금을 떳떳하게 요구하고 이 집에서 쫓겨나지 않을 임차인의 대단한 권리! 이사 당일 전입신고와 확정일자를 받으면 다음 날 새벽 0시부터 강력한 보호막이 생깁니다."
    
### ② 안전도 진단 ➔ "HUG 가입 가능 여부 실시간 시뮬레이션"

임차인들이 가장 원하는 구체적인 정보는 "그래서 이 집 HUG 전세보증보험 가입 돼요? 안 돼요?"입니다.

- 백엔드 연산 결과 부채 비율이 90%를 넘으면 AI가 가입 불가 사유를 정확하게 짚어줍니다.
    
- _가이드 문구 예시:_ "도연님, 이 집은 매매가 대비 융자가 많아 현재 허그(HUG) 보증보험 가입 기준을 초과합니다. 만약 계약을 진행하시려면 집주인에게 '잔금 치를 때 대출을 일부 상환하여 말소한다'는 조건의 특약을 요구하셔야 합니다."
    
### ③ 디데이 리마인드 알림 ➔ "보증금 임무(Mission) 타임라인"

단순 일정을 보여주는 걸 넘어, 마치 **게임을 하는 것처럼 퀘스트(Quest) 형태**로 정보를 풍부하게 제공합니다.

- **계약 당일:** 🔒 _임무 완료 보상: 대항력 확보 준비_ ➔ "계약서 쓰셨나요? 중개사가 준 등기부등본의 발행 일시가 '오늘 날짜'가 맞는지 1초만 확인하세요. 며칠 전 서류라면 그사이 빚이 생겼을 수 있습니다!"
    
- **이사 당일:** 🏃‍♂️ _임무: 동주민센터 방문 퀘스트_ ➔ "짐 풀기 전에 스마트폰이나 주민센터로 달려가 '전입신고'와 '확정일자'부터 도장 찍으세요. 오늘 밤을 넘기면 법적 순위가 밀릴 수 있습니다."

# ➕부가적인 서비스
## 🗺️ 1. 주변 인프라 정보 수집 및 구현 방법

유저가 매물 주소를 입력하거나 등기부를 올려 주소가 확정되면, 백엔드에서 해당 주소의 **위도·경도 좌표**를 기반으로 주변 시설을 탐색합니다.

### ① 대중교통 거리 (지하철역 / 버스 정류장)
- **활용 API:** 국토교통부 국토지리정보원 API 또는 **카카오 로컬(Local) API / 네이버 클라우드 플레이스 API**
    
- **구현 방식:** 카카오/네이버 로컬 API의 '카테고리 검색(지하철역, 버스정류장)' 기능을 사용합니다. 매물 좌표 기준 반경 500m~1km 이내의 역들을 리스트업하고, 직선거리가 아닌 도보 시간(예: 도보 7분, 450m)으로 변환하여 프론트엔드에 전달합니다.
    
### ② 편의 시설 (편의점, 대형마트, 코인세탁소)
- **활용 API:** 카카오 로컬 API (카테고리 코드: `CS2` 편의점, `MT1` 대형마트 등)
    
- **구현 방식:** 1인 가구 임차인에게 가장 중요한 '편세권(편의점)'과 '세탁권(코인세탁소)' 정보를 수집합니다. 특히 "가장 가까운 편의점까지 도보 2분" 같은 정보를 대시보드에 요약해 줍니다.
    
### ③ 의료 서비스 (응급실, 대형병원, 야간약국)
- **활용 API:** 공공데이터포털의 **'국립중앙의료원_전국 병의원 및 약국 위치 정보 서비스' API**
    
- **구현 방식:** 단순 병원 개수보다 임차인에게 실질적인 안심을 주는 '응급실 운영 병원'이나 **'연중무휴/야간 약국'** 정보만 필터링하여 매핑해 줍니다. "갑자기 아플 때 바로 갈 수 있는 병원이 반경 1km 내에 2곳 있습니다"라는 메시지를 던지는 방식입니다.

```text
나:
일단 프로젝트에서 제공할 서비스로는

1. 어려운 부동산/계약 용어 정리 및 요약
2. 계약하려는 집의 안전도(빚이 있는지, 집 소유주 정보....)
3. 주변 시설 정보 제공
4. 층간 소음 빈도 정보 제공
5. 부동산 계약 서류 스캔 및 체크리스트 작성
6. 전입신고/서류 제출 기간 등을 리마인드(알림)

이렇게 일단 설정을 했는데, 이 서비스가 기존 부동산 관련 서비스와 관련해서 차별점이 있는지 의문이야ㅠㅠㅠ 
```

>도연님, 기획한 6가지 핵심 기능들이 아주 촘촘하게 잘 모였습니다!
>
>충분히 들 수 있는 의문이에요. "단순히 정보만 보여주는 거면 네이버 부동산, 직방, 호갱노노랑 뭐가 다르지?"라는 생각이 들 수 있죠. 하지만 **기존 대기업 서비스들은 치명적인 한계**를 가지고 있고, 도연님의 프로젝트는 그 틈새를 완벽하게 파고들고 있습니다.
>
>기존 서비스와 확실하게 구별되는 이 프로젝트만의 강력한 차별점 3가지**를 정리해 드릴게요. 면접관이 "기존 서비스랑 뭐가 달라요?"라고 물어봤을 때 이대로 답변하시면 됩니다.

## 🎯 1. '임대인(중개사)' 중심이 아닌, 철저한 '임차인 보호' 플랫폼

- **기존 서비스 (직방, 다방, 네이버 부동산):** 그들의 진짜 고객은 돈을 내고 매물을 올리는 '공인중개사와 임대인'입니다. 따라서 앱의 목적은 '매물 홍보와 빠른 계약 유도'입니다. 불리한 정보(융자가 많다거나, 층간소음이 심하다거나)를 적극적으로 보여줄 이유가 전혀 없습니다.
    
- **이 프로젝트의 차별점**: 오직 **'임차인(세입자)'의 돈과 안전만 생각하는 독립적인 가드 서비스**입니다. 중개사가 숨기고 싶어 하는 등기부의 빚, 지역 소음 통계 등을 가감 없이 '해독(Decoding)'해서 임차인의 눈앞에 대령합니다.
    
## 🤖 2. 파편화된 정보를 한곳에 압축한 '제로클릭 올인원 케어'

지금 임차인들이 계약 전 안전을 확인하려면 다음과 같은 지옥의 여정을 거쳐야 합니다.

> 인터넷 등기소에서 등기부 열람 ➔ 등기부 들고 커뮤니티에 "이 집 안전한가요?" 질문 ➔ 네이버 지도 켜고 지하철역 거리 계산 ➔ 호갱노노 켜고 층간소음 리뷰 검색 ➔ 메모장에 체크리스트 작성 ➔ 캘린더에 전입신고 날짜 기록...

- 이 프로젝트의 차별점:** 유저는 그저 **주소 입력과 서류 스캔(업로드) 딱 한 번**만 하면 됩니다. 그러면 `1. 용어 요약`, `2. 안전도 계산`, `3. 주변 시설`, `4. 소음 통계`, `5. 체크리스트 생성`, `6. 알림 등록`까지 백엔드와 AI가 알아서 한 바구니에 담아 **`수집.zip` 파일처럼 압축해서 제공**합니다. 이 편리함의 격차가 엄청난 차별점입니다.
    
## ✍️ 3. 단순 '정보 조회'를 넘어선 '실행(Action) 중심의 UX'

- **기존 서비스:** 아파트 실거래가나 등기부등본을 보여주는 서비스(예: 아실, 리치고 등)는 많지만, "그래서 내가 지금 뭘 해야 하지?"에 대한 답은 주지 않습니다.
    
- **이 프로젝트의 차별점**: "행동하게 만드는 서비스"입니다. 서류 분석 결과를 토대로 현장에서 바로 쓸 수 있는 `맞춤형 특약사항 문구`를 복사해 주고, 계약 날짜에 맞춰 `오늘 당장 전입신고 하세요!`라고 등을 떠밉니다. AI 에이전트가 단순 챗봇이 아니라 임차인의 **'페이스메이커(동행자)'** 역할을 하는 것이죠.

# 🔩기술적 관점
## 🤖 AI 에이전트 적용하기

단순히 "주변에 병원 3개, 지하철역 1개 있습니다"라고 텍스트만 나열하면 네이버 부동산이나 직방과 차별화가 되지 않습니다. 프로젝트 정체성에 맞게 **AI가 임차인의 라이프 스타일에 맞춰 이 인프라를 해석**해 주도록 기획합니다.

## 🤖 ZIPT 핵심 AI 에이전트 프롬프트(System Prompt) 설계

AI가 헛소리(할루시네이션)를 하지 않고 정확히 임차인 편에서 법률·인프라 데이터를 해독하도록 구조화된 프롬프트를 주입해야 합니다.

```text
[System Role]
당신의 이름은 'ZIPT(집PT)'이며, 대한민국 전/월세 시장에서 정보 비대칭성으로 고통받는 2030 사회초년생 임차인을 위한 '전문 부동산 권리분석가이자 든든한 계약 페이스메이커'입니다. 임대인이나 중개사 눈치를 보지 않고, 오직 임차인의 보증금을 지키기 위해 철저히 임차인의 시선에서 서류와 데이터를 해독합니다.

[Input Data]
백엔드 서버로부터 다음과 같은 마스킹된 정형/비정형 데이터를 제공받습니다:
1. 등기부등본/건축물대장 OCR 텍스트
2. 국토교통부 제공 해당 매물 실거래가/시세 데이터
3. 공공데이터 기반 자치구별 층간소음 및 인프라(지하철, 편의점, 병원 등) 데이터
4. 유저가 선택한 계약 유형 (예: 일반전세, 월세, HUG 보증보험 연계 등)

[Output Guide & Constraint]
1. 어조: 친근하면서도 전문적이고 든든한 톤앤매너를 유지하세요. (예: "~입니다", "도연님, 이 조항은 꼭 짚고 넘어가야 해요!")
2. 출력 형식: 백엔드가 즉시 파싱하여 프론트엔드 UI에 띄울 수 있도록 반드시 '구조화된 JSON 형식'으로만 답변하세요. 줄글 설명은 `ai_report` 필드에 담아주세요.
3. 주의사항: 조금이라도 권리 관계가 불투명하거나 융자 비율이 높다면 주저하지 말고 위험(DANGER) 경고를 날리세요.
```

  "risk_grade": "SAFE | CAUTION | DANGER",
  "document_summary": {
    "ownership": "갑구 분석 요약",

  },

## 🛠️ 백엔드 핵심 기술 스택 추천
- **Main API 서버:** **FastAPI (Python)** 또는 **Spring Boot**
    - _추천:_ PDF/이미지 처리와 AI(LLM) 파이프라인 연동이 많으므로 **FastAPI**가 생산성 면에서 유리할 수 있습니다. 다만 익숙한 프레임워크를 선택하셔도 무방합니다.
    
- **OCR 엔진:** 유저가 올린 등기부등본 PDF나 사진에서 텍스트를 추출하기 위해 **Upstage Document OCR API**나 **Naver CLOVA OCR**을 연동합니다. (이 경험 자체가 포트폴리오에서 엄청난 가산점입니다.)

## 💻 풀스택 개발자를 위한 한 줄 구현 아키텍처 팁
1. **지오코딩(Geocoding):** 유저가 입력한 주소(텍스트)를 카카오 주소 API를 통해 위도/경도(Coordinate) 숫자로 변환해 DB에 저장합니다.
    
2. **API 호출 최적화 (Redis 캐싱):** 유저들이 같은 동네(예: 역삼동)의 다른 빌라들을 검색할 때마다 매번 카카오 API를 치면 비용과 속도에 손해가 큽니다. 변하지 않는 지역 인프라 정보는 **Redis에 주소 구역별로 캐싱**해 두었다가 빠르게 서빙하는 로직을 구축하면 포트폴리오에서 기술적으로 엄청난 칭찬을 받을 수 있습니다.
    
3. **프론트엔드 Map 시각화:** 카카오맵 API 위에 내 매물 위치를 핀으로 찍고, 주변의 편의시설/지하철/병원을 카테고리별 필터 버튼(클릭 시 마커 표시/숨김)으로 직관적으로 시각화해 줍니다.
