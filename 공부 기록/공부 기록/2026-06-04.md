# IaC(Infrastructure As Code)
> **“인프라를 코드로 정의하고 관리하는 방식”**
> 즉, **서버, 네트워크, 보안, 데이터베이스** 등을 사람이 클릭해서 설정하는 게 아니라, **코드로 작성하고 자동화**하여 설정한다.
> **코드를 통해 관리하고 프로비저닝하는 것을 의미한다.**
> IaC는 코드를 활용하기 때문에 작성의 용이성, 재사용성, 유지보수의 용이성 등의 장점을 가진다.

*프로비저닝(Provisioning) : 사용자나 시스템이 즉시 IT 자원 및 서비스를 이용할 수 있도록 필요한 환경을 준비하고 공급하는 과정*

### 왜 IaC를 사용할까?

| 이유              | 설명                                            |
| --------------- | --------------------------------------------- |
| **✅ 자동화**       | 클릭 없이 코드 한 줄로 인프라 생성  가능(DevOps의 핵심)          |
| **✅ 버전 관리**     | Git으로 인프라 상태 추적 가능 → 롤백도 쉬움                   |
| **✅ 재현 가능**     | 동일한 인프라를 여러 환경(`dev`/`test`/`prod`)에 복사 생성 가능 |
| **✅ 사람 실수 최소화** | 수동 클릭보다 정확함(오타, 누락 방지)                        |
| **✅ 협업 효율성**    | 개발자 간 코드로 인프라를 리뷰하고 공유 가능                     |

### IaC 도구의 종류

| 도구                    | 특징                                        |
| --------------------- | ----------------------------------------- |
| **Terraform**         | 가장 인기있는 클라우드 플랫폼 독립 IaC 도구                |
| **AWS CloudFormaion** | AWS 전용 IaC 도구                             |
| **Pulumi**            | 다양한 언어(JS, Python 등)로 IaC 작성              |
| **Ansible**           | 서버 설정 자동화에 특화(상태 기반 아님)                   |
| **CDK(AWS CDK)**      | 실제 프로그래밍 언어로 인프라 구성(TypeScript, Python 등) |

# Terraform
> **“멀티 클라우드 인프라를 코드로 선언하고 자동으로 배포하는 도구”**

Open Source Infrastructure As Code

> HashiCorp 사에서 만든 솔루션 중 하나이다. Infrastructure를 생성하는 코드를 생성하면 이 코드가 퍼블릭 클라우드와 연결을 해서 Provider라 는 객체를 통해 상호작용하면서 네트워크 설정이나 EC2 등을 생성해준다. 한번 작성해 놓은 코드를 이용해서 ==항상 동일하게(멱등성)== 인프라를 유지할 수가 있다. AWS, Azure, GCP, Kubernetes 등 다양한 클라우드 인프라를 하나의 문법으로 제어 가능하다. .tf 파일(HCL 언어)로 인프라를 정의하고 terraform apply로 자동 구축한다.

### Terraform을 이용한 배포
- 개발자가 IAC 즉 인프라를 제어하는 Configuration File을 HCL 언어를 이용해 코드를 작성한 다.
- S3, VPC 등을 별도로 모듈화를 해서 만든다.
- 테라폼이 실행 플랜을 빌드해서 보여준다. 즉 가상으로 실행을 해보는 것이라고 보면 된다.
- 에러가 없으면 Apply를 한다. 테라폼은 실행하면서 **프로비저닝(필요한 만큼 자원을 자동 또는 수동으로 준비하고 사용할 수 있게 만드는 것)** 을 한다.

### Terraform 기본 동작 구조

1. Write : 인프라 환경을 HCL언어로 리소스 정의
2. Plan : 정의된 리소스들을 생성, 수정, 삭제하기 위해 실행 계획을 확인
3. Apply : 확인된 실행 계획을 리소스 종속성을 고려하여 올바른 순서대로 수행

- 개발자가 code 를 작성 > IaC > plan 즉 ping 을 날려보고 문제가 없는지 결과값이 어떨지 plan 을 보고 output 을 샘플 코드를 본다.

- **일관성 있고 신뢰성 있게 인프라를 관리할 수 있게 된다.**

### Terraform의 구성 요소

|              |                                                |
| ------------ | ---------------------------------------------- |
| **provider** | 테라폼으로 생성할 인프라의 종류(AWS, GCP)                    |
| **resource** | 테라폼으로 실제 생성할 인프라 지원(EC2 인스턴스, S3 버킷, VPC, RDS) |
| **state**    | 테라폼을 통해 생성한 자원의 상태: 테라폼 코드로 만들어진 자원            |
| **output**   |                                                |
| **module**   |                                                |
| **remote**   |                                                |

### Terraform 기본 명령어

| 명령어         | 기능                                            |
| ----------- | --------------------------------------------- |
| **init**    | 테라폼 명령어 사용을 위한 각종 설정 진행                       |
| **plan**    | 테라폼으로 작성한 코드의 실행 시, 예측 결과를 보여줌                |
| **apply**   | 테라폼 코드로 실제 인프라를 생성하는 명령어                      |
| **import**  | 이미 만들어진 자원을 테라폼 state 파일로 옮기는 명령어             |
| **state**   | 테라폼 state를 다루는 명령어(`mv`, `push` 와 같은 명령어가 있음) |
| **destroy** | 생성된 자원들을 state 파일 기준으로 모두 삭제하는 명령어            |

```bash
terraform fmt // 코드 예쁘게 정리
terraform validate // 코드가 Terraform 문법상 맞는지 검사
```

- `terraform fmt` : Terraform 코드 서식을 자동으로 정리하는 명령어
	- 예를 들어 들여쓰기, 공백, 정렬 같은 스타일을 Terraform 표준 형식으로 맞춰줍니다. 인프라를 생성하거나 변경하지는 않고, .tf 파일 내용의 모양만 정리합니다.

- `terraform validate` : Terraform 코드 문법과 구성 오류를 검사하는 명령어
	- 예를 들어 리소스 블록 문법이 틀렸는지, 변수 참조가 잘못됐는지, provider 설정이 유효한지 등을 확인합니다. 이것도 실제 AWS 리소스를 만들지는 않습니다.

```bash
// 실행 순서
terraform fmt       // 코드 예쁘게 정리
terraform validate  // 코드가 Terraform 문법상 맞는지 검사
terraform plan      // 실제로 뭘 만들지 미리 보기
terraform apply     // 실제 AWS에 생성

terraform destroy // 모든 resources 삭제
```
