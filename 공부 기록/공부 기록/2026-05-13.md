# `@ResponseBody` vs `@RestController`
## 1. @ResponseBody란?

### 📘 정의
`@ResponseBody`는 **메서드의 반환값을 View(화면)** 으로 해석하지 않고, **HTTP 응답 본문(body)** 으로 직접 전송하라고 알려주는 어노테이션

즉,
> *“이 메서드는 JSP로 가지 말고, 바로 응답 데이터를 클라이언트에게 보내라!”* 라고 Spring MVC에게 명령하는 역할

---

## ⚙️ 2. 동작 원리
Spring MVC의 기본 흐름

```
요청 → DispatcherServlet → Controller → ViewResolver → JSP or HTML 렌더링
```

하지만, `@ResponseBody`를 붙이면 **ViewResolver 단계를 건너뛰고**, **`HttpMessageConverter`**가 실행되어 다음과 같은 변환을 수행]

# Builder 패턴
> Builder 패턴은 **복잡한 객체 생성 로직을 단순화**하고, **가독성 있고 유지보수하기 쉬운 객체 생성 방법을 제공하는 생성 패턴(Creational Pattern)** 중 하나이다.

즉,
- 생성자의 파라미터가 많거나,
- 선택적(옵션) 필드가 많은 객체를
- **안정적이고 가독성 있게 생성하기 위한 패턴**이다.

## 2. 왜 필요한가? (필요성)

### 📌 기존 방식의 문제 : 생성자나 setter가 많을 때의 혼란
예를 들어 아래처럼 `User` 객체를 만든다고 가정해보자.

```java
User user = new User("홍길동", 25, "developer", "seoul", "010-1111-2222");
```

이렇게 인자가 많으면 다음과 같은 문제가 생긴다.
- 인자 순서를 헷갈리기 쉽다.
- 코드의 의미가 불명확하다. (이 값이 어떤 필드인지 바로 알기 어려움)
- 생성자 오버로딩이 많아져서 유지보수가 힘들다.

## 3. Builder 패턴의 개념과 동작
Builder 패턴은 이런 문제를 해결하기 위해 **“필드 설정 메서드들을 체이닝(Chaining)”** 하여 **명시적으로 객체를 구성**하는 방식을 제공한다.

즉,
- 필요한 값만 지정하고,
- 마지막에 `.build()`로 객체를 완성한다.

## ✅ 4. Builder 패턴 예제

```java
public class User {
    private final String name;
    private final int age;
    private final String job;
    private final String address;
    private final String phone;

    // private 생성자 — Builder 외부에서 직접 생성 불가
    private User(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
        this.job = builder.job;
        this.address = builder.address;
        this.phone = builder.phone;
    }

    // 정적 내부 클래스 Builder
    public static class Builder {
        private String name;
        private int age;
        private String job;
        private String address;
        private String phone;

        public Builder name(String name) {
            this.name = name;
            return this; // 체이닝
        }

        public Builder age(int age) {
            this.age = age;
            return this;
        }

        public Builder job(String job) {
            this.job = job;
            return this;
        }

        public Builder address(String address) {
            this.address = address;
            return this;
        }

        public Builder phone(String phone) {
            this.phone = phone;
            return this;
        }

        // 최종 객체 생성
        public User build() {
            return new User(this);
        }
    }

    @Override
    public String toString() {
        return String.format("User{name='%s', age=%d, job='%s', address='%s', phone='%s'}", name, age, job, address, phone);
    }
}
```

# Jackson-databind 라이브러리
## 1. Jackson-databind란 무엇인가?

### 🧩 정의
*`jackson-databind`*는 **Java 객체(Object)** ↔ **JSON 데이터** 간 변환(**직렬화/역직렬화**)을 담당하는 **Jackson 라이브러리의 핵심 모듈**

### 🔍 Jackson 전체 구조
Jackson은 3개의 주요 모듈로 구성되어 있다.

| 모듈명                   | 역할                                          |
| --------------------- | ------------------------------------------- |
| `jackson-core`        | JSON 파싱과 생성의 가장 기본 기능 (저수준 API)             |
| `jackson-annotations` | `@JsonProperty`, `@JsonIgnore` 등의 어노테이션 제공  |
| `jackson-databind`    | POJO <-> JSON 변환 (고수준 API, ObjectMapper 제공) |

→ 즉, **`jackson-databind`는 위 두 모듈을 포함하여 실제로 우리가 자주 쓰는 `ObjectMapper`를 제공하는 핵심 모듈이다.**

---
### 🧠 직렬화(Serialization) / 역직렬화(Deserialization)
| 변환 방향    | 설명                    | 예시                                    |
| -------- | --------------------- | ------------------------------------- |
| **직렬화**  | Java 객체 → JSON 문자열 변환 | `User` 객체 → `{"name":"홍길동","age":20}` |
| **역직렬화** | JSON 문자열 → Java 객체 변환 | `{"name":"홍길동","age":20}` → `User` 객체 |

### ⚙예제 코드

```java
import com.fasterxml.jackson.databind.ObjectMapper;

public class JacksonExample {
    public static void main(String[] args) throws Exception {
        ObjectMapper mapper = new ObjectMapper();

        //  Java 객체 → JSON 문자열
        User user = new User("홍길동", 25);
        String json = mapper.writeValueAsString(user);
        System.out.println(json); // {"name":"홍길동","age":25}

        //  JSON 문자열 → Java 객체
        String input = "{\"name\":\"이순신\",\"age\":30}";
        User parsed = mapper.readValue(input, User.class);
        System.out.println(parsed.getName()); // 이순신
    }
}

class User {
    private String name;
    private int age;

    // 기본 생성자와 getter/setter 필수
    public User() {}
    public User(String name, int age) { this.name = name; this.age = age; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }
}
```

# ResponseEntity 응답 객체
## 1. ResponseEntity란?

### 📘 정의
`ResponseEntity`는 **HTTP 응답 전체를 표현하는 객체**

즉,
> “**응답 본문(Body) + 응답 헤더(Header) + 응답 상태 코드(Status Code)**” 를 모두 제어할 수 있는 Spring의 응답 래퍼(Wrapper) 객체이다.

---
## 2. 기본 구조

```java
public class ResponseEntity<T> extends HttpEntity<T> {
    private final HttpStatus status;
}
```

|구성요소|설명|
|---|---|
|**T body**|응답 본문 (예: JSON 데이터, 문자열, 객체 등)|
|**HttpHeaders headers**|응답 헤더|
|**HttpStatus status**|HTTP 상태 코드 (200, 400, 404 등)|

---
## 3. 기본 사용 예시

```java
@RestController
@RequestMapping("/api")
public class UserController {

    @GetMapping("/user")
    public ResponseEntity<String> getUser() {
        return new ResponseEntity<>("성공적으로 조회되었습니다.", HttpStatus.OK);
    }
}
```

➡️ 결과 응답:

```console
HTTP/1.1 200 OK
Content-Type: text/plain;charset=UTF-8

성공적으로 조회되었습니다.
```

## 4. 정적 팩토리 메서드 사용 (가독성 향상)
실무에서는 `ResponseEntity.ok()` 같은 **정적 메서드 빌더 방식**을 자주 사용한다.

```java
@GetMapping("/user")
public ResponseEntity<String> getUser() {
    return ResponseEntity.ok("성공적으로 조회되었습니다.");  // 200 OK
}
```

### 주요 팩토리 메서드

|메서드|설명|
|---|---|
|`ok(body)`|200 OK 응답|
|`status(HttpStatus)`|상태 코드를 지정할 수 있는 빌더|
|`badRequest()`|400 Bad Request 응답|
|`notFound()`|404 Not Found 응답|
|`noContent()`|204 No Content 응답|

---
## 5. JSON 객체 응답 예제
```java
@GetMapping("/user")
public ResponseEntity<User> getUser() {
    User user = new User("홍길동", 25);
    
    return ResponseEntity.ok(user);
}
```

➡️ 결과 응답:

```
HTTP/1.1 200 OK
Content-Type: application/json

{
  "name": "홍길동",
  "age": 25
}
```

> **@RestController + ResponseEntity** 조합은 Spring Boot에서 JSON 응답을 만들 때 가장 많이 사용된다.

---
## 6. 상태 코드 제어 예제

```java
@GetMapping("/user/{id}")
public ResponseEntity<User> getUser(@PathVariable Long id) {
    if (id == 0) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                             .body(null);
    } else if (id == 999) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                             .body(null);
    }

    User user = new User("홍길동", 25);
    
    return ResponseEntity.status(HttpStatus.OK).body(user);
}
```

➡️ 요청 `/user/0` → **400 Bad Request**
➡️ 요청 `/user/999` → **404 Not Found**
➡️ 요청 `/user/1` → **200 OK + JSON 데이터**

## 7. 응답 헤더 설정하기
`ResponseEntity`는 헤더도 함께 제어할 수 있다.

```java
@GetMapping("/download")
public ResponseEntity<byte[]> downloadFile() {
    byte[] fileData = "파일 내용".getBytes(StandardCharsets.UTF_8);

    HttpHeaders headers = new HttpHeaders();
    headers.add(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=test.txt");
    headers.add(HttpHeaders.CONTENT_TYPE, "text/plain; charset=UTF-8");

    return new ResponseEntity<>(fileData, headers, HttpStatus.OK);
}
```

➡️ 클라이언트는 다운로드 팝업이 뜨면서 파일을 받을 수 있다.

---
## 8. ResponseEntity vs @ResponseBody 비교

| 구분       | `@ResponseBody`  | `ResponseEntity`                  |
| -------- | ---------------- | --------------------------------- |
| 응답 제어 수준 | **Body만 전송**     | **Body + Header + Status 모두 제어**  |
| 리턴 타입    | 단순 객체 / 문자열      | ResponseEntity<T>                 |
| 사용 목적    | 간단한 JSON, 텍스트 응답 | RESTful API 응답 전체 제어              |
| 상태 코드 변경 | 불가능 (기본 200)     | 가능 (`HttpStatus` 지정 가능)           |
| 예시       | `return user;`   | `return ResponseEntity.ok(user);` |
✅ **즉, 단순 응답은 @ResponseBody**, 복합 응답(상태 코드 + 헤더 포함)은 **ResponseEntity** 사용이 권장된다.

---
## 9. 예외 처리(@ExceptionHandler)와 함께 사용하는 패턴
Spring의 예외 처리에서 `ResponseEntity`는 필수적으로 등장

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<Map<String, String>> handleUserNotFound(UserNotFoundException e) {
        Map<String, String> error = Map.of("error", e.getMessage());
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(error);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, String>> handleGeneral(Exception e) {
        Map<String, String> error = Map.of("error", "서버 내부 오류 발생");
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(error);
    }
}
```

➡️ 이렇게 하면
**모든 API의 에러 응답 형식을 통일하고, 상태 코드도 명확히 제어**할 수 있다.

---
## 10. 정리 요약

|항목|설명|
|---|---|
|클래스|`ResponseEntity<T>`|
|역할|HTTP 응답 전체(본문, 헤더, 상태코드) 제어|
|주 사용처|REST API 응답, 예외 처리 응답|
|장점|상태 코드 및 헤더를 직접 지정 가능|
|자주 사용하는 팩토리 메서드|`ok()`, `status()`, `badRequest()`, `notFound()`|
|자주 함께 쓰이는 어노테이션|`@RestController`, `@ExceptionHandler`, `@RestControllerAdvice`|
|반환 구조|`ResponseEntity<응답객체>`|

---
## ✅ 핵심 한 줄 요약

> ResponseEntity는 Spring에서 HTTP 응답을 완벽히 제어하기 위한 객체로, **본문(Body)**, **상태 코드(Status)**, **헤더(Header)** 를 함께 구성할 수 있다.
> 
> → 단순 JSON이면 `@ResponseBody`,
> → 명확한 API 응답 제어가 필요하면 **ResponseEntity** 사용!
