# JPA
### JPA 등장 배경
> **JDBC(Java DataBase Connectivity)** 는 Java에서 데이터베이스에 접속하고, 데이터 처리 구현에 사용되는 Java API이다.

# 1. JPA 소개
SQL을 확인하기 전까지는 엔티티를 신뢰하기 어렵다.

```java
class MemberService {
	...
	public void process(String id) {
		Member member = memberDAO.find(id);
		member.getTeam(); // Null 값이 나올지 아닐지 알 수 없다는 것(신뢰도 X)
		member.getOrder().getDelivery();
	}
}
```

- 표준

# JPA의 주요 인터페이스

## EntityManager / FactoryEntityManager / EntityTransaction
DB와의 연결, 쿼리 실행, 트랜잭션 관리를 담당하는 것이 바로 `EntityManagerFactory` / `EntityManager` / `EntityTransaction` 세 가지

```text
EntityManagerFactory  →  EntityManager  →  EntityTransaction
       (공장)              (작업자)          (트랜잭션 관리)
```

### 1️⃣ EntityManagerFactory (엔티티 매니저 팩토리)
> **엔티티 매니저를 만드는 "공장"**

#### 💡 개념
- **`EntityManager`**를 **생성하는 역할**을 하는 **싱글톤(공유)** 객체.
- **DB와의 연결 설정, 캐싱, 메타데이터 초기화 등**을 담당.
- 보통 **애플리케이션 전체에서 하나만 생성**

#### ✅ 사용 예시

```java
EntityManagerFactory emf =
    Persistence.createEntityManagerFactory("my-persistence-unit");

```

> 🔹 "my-persistence-unit"은 persistence.xml에 정의한 이름이다.

#### ⚙️ 역할 요약

|역할|설명|
|---|---|
|JPA 설정 읽기|`persistence.xml`의 DB 설정 정보 로드|
|EntityManager 생성|DB 작업을 수행할 EntityManager 객체 생성|
|리소스 관리|DB 커넥션 풀, 캐시, 메타데이터 초기화 관리|

---
### 2️⃣ EntityManager (엔티티 매니저)
> **엔티티를 관리하고 DB 작업을 수행하는 핵심 객체**

#### 💡 개념
- 엔티티의 **저장(Persist)**, **조회(Find)**, **수정(Update)**, **삭제(Remove)** 등 모든 JPA 동작을 수행하는 “실제 일꾼”.
- Hibernate 기준으로는 하나의 **세션(Session)** 역할
- ==**스레드 간에 공유하지 않는다.**==
  → 즉, **요청(Request)** 단위로 새로 만들어서 사용해야 한다.

#### ✅ 주요 메서드

|메서드|역할|
|---|---|
|`persist(entity)`|엔티티를 DB에 저장 (INSERT)|
|`find(EntityClass, id)`|기본 키로 엔티티 조회|
|`remove(entity)`|엔티티 삭제 (DELETE)|
|`merge(entity)`|detached 상태의 엔티티를 다시 영속화 (UPDATE)|
|`createQuery(...)`|JPQL 또는 네이티브 쿼리 실행|
|`getTransaction()`|트랜잭션 관리 객체 반환|
### ✅ 사용 예시

```java
EntityManager em = emf.createEntityManager();
```

→ 이렇게 얻은 `EntityManager`로 DB 작업을 한다.

---
### 3️⃣ EntityTransaction (엔티티 트랜잭션)
> **트랜잭션(Commit/Rollback)을 제어하는 객체**

#### 💡 개념
- JPA는 기본적으로 **트랜잭션 안에서만** 데이터 변경이 가능.
- `EntityManager`로부터 가져와서 사용한다.

#### ✅ 사용 예시

```java
EntityTransaction tx = em.getTransaction();

try {
    tx.begin(); // 트랜잭션 시작
    em.persist(member); // INSERT
    tx.commit(); // 커밋
} catch (Exception e) {
    tx.rollback(); // 실패 시 롤백
}
```

---
### 🔁 전체 흐름 예제

```java
public class JpaMain {
    public static void main(String[] args) {
        // 1. 엔티티 매니저 팩토리 생성 (앱 전체에서 1개)
        EntityManagerFactory emf =
                Persistence.createEntityManagerFactory("hello");
        // 2. 엔티티 매니저 생성 (요청 단위)
        EntityManager em = emf.createEntityManager();
        // 3. 트랜잭션 시작
        EntityTransaction tx = em.getTransaction();
        tx.begin();
        try {
            // 4. 엔티티 생성 및 저장
            Member member = new Member(); // @Entity
            member.setId(1L);
            member.setName("Kosta295");
            em.persist(member);
            // 5. 커밋 (DB 반영)
            tx.commit();
            
        } catch (Exception e) {
            tx.rollback();
        } finally {
            // 6. 자원 해제
            em.close();
        }
        emf.close(); // 앱 종료 시 팩토리 닫기
    }
}
```

#### ⚙️ 동작 요약 표

|객체|역할|생성 시점|사용 주기|
|---|---|---|---|
|`EntityManagerFactory`|엔티티 매니저 생성 공장|애플리케이션 시작 시 1회|애플리케이션 전체에서 공유|
|`EntityManager`|엔티티 CRUD 수행|요청마다 새로 생성|요청(Request) 단위|
|`EntityTransaction`|트랜잭션 시작/커밋/롤백 제어|작업 단위마다|트랜잭션 단위|

---
## 실무에서의 사용 (Spring Boot)

**Spring 환경에서는 위 과정을 대부분 자동으로 처리한다.**
- `EntityManagerFactory` → **Spring이 자동 관리 (Bean 등록됨)**
- `EntityManager` → **스프링이 트랜잭션 단위로 자동 주입 (`@PersistenceContext`)**
- `EntityTransaction` → **`@Transactional` 애너테이션으로 자동 제어**

```java
@Service
@Transactional
public class MemberService {
    @PersistenceContext
    private EntityManager em;

    public void saveMember(Member member) {
        em.persist(member); // 트랜잭션은 @Transactional이 관리
    }
}
```

---
### 한 줄 요약
| 객체                       | 한 줄 정의                             |
| ------------------------ | ---------------------------------- |
| **EntityManagerFactory** | “엔티티 매니저를 만들어주는 공장 (앱 전체에서 1개)”    |
| **EntityManager**        | “엔티티의 CRUD를 실제 수행하는 관리자 (요청 단위)”   |
| **EntityTransaction**    | “트랜잭션의 시작·커밋·롤백을 담당하는 관리자 (작업 단위)” |

# `@GeneratedValue`

## 3. 각 전략별 동작 방식
### (1) `IDENTITY`

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

- DB의 **AUTO_INCREMENT** 기능을 사용
- 예: MySQL, MariaDB
- ==**insert 시점에 바로 ID가 생성됨**==
- JPA가 `persist()` 할 때 즉시 SQL `INSERT`를 실행해야 함 → **지연(insert delay)** 불가

    - **참고**
        `@GeneratedValue(strategy = GenerationType.IDENTITY)` 는 **DB의 auto_increment 컬럼**을 이용하는 전략이다. 즉, **기본 키 생성을 DB에 위임**하기 때문에, 엔티티 매니저가 직접 식별자를 알 수 없다. JPA는 엔티티를 영속화할 때 반드시 **식별자 값**을 알아야 1차 캐시에 저장할 수 있기 때문에,
        
        `em.persist()` 시점에 **즉시 INSERT SQL을 실행하여 DB로부터 생성된 ID 값을 가져온다.**


---
### 🔹 쓰기 지연이 적용되지 않는 이유
`IDENTITY` 전략을 사용하면 아래 과정이 일어난다.
        
1. `em.persist(member)` 호출 시
	→ JPA는 member의 ID 값을 알기 위해 **즉시 INSERT SQL 실행**
	→ DB에서 생성된 ID(auto_increment 값)를 조회하여 `member.id`에 세팅
	→ 이후 1차 캐시에 저장
	
2. `em.getTransaction().commit()` 시
	→ 이미 INSERT가 실행되었기 때문에, 커밋 시점에는 별도의 쓰기 지연 SQL이 없다.

즉, **`IDENTITY` 전략에서는 **쓰기 지연 저장소(batch insert)**를 사용할 수 없다.**
왜냐하면 INSERT를 미루면 ID를 모르는 상태로 1차 캐시에 넣을 수 없기 때문이다.


---
### 🔹 반면 `SEQUENCE` / `TABLE` 전략의 경우
- `SEQUENCE`: JPA가 먼저 시퀀스 값을 미리 조회(`SELECT nextval(...)`)해서 ID를 설정한 뒤
- INSERT를 **쓰기 지연 저장소에 보관** → **commit 시점에 실행**
- `TABLE`: 별도의 키 생성용 테이블에서 ID를 읽은 뒤, 마찬가지로 commit 시점에 INSERT 실행

---
### 🔹 정리
| 전략       | ID 생성 주체            | INSERT 실행 시점        | 쓰기 지연 저장소 사용 |
| -------- | ------------------- | ------------------- | ------------ |
| IDENTITY | DB (auto_increment) | `persist()` 호출 시 즉시 | ❌ 불가         |
| SEQUENCE | DB 시퀀스              | 커밋 시점 (쓰기 지연)       | ✅ 가능         |
| TABLE    | 별도 키 테이블            | 커밋 시점 (쓰기 지연)       | ✅ 가능         |
| AUTO     | DB Dialect에 따라 다름   | 전략에 따라 다름           | 전략에 따라 다름    |


---
요약하자면,

> ✅ IDENTITY 전략을 사용하면 em.persist() 호출 시점에 즉시 INSERT가 실행되고,
> ❌ 쓰기 지연 저장소를 통한 커밋 시점 실행은 적용되지 않는다.


🟡 특징:
- DB가 ID를 만들어줌
- JPA는 INSERT 후에 ID 값을 가져옴

# `@DynamicUpdate` 와 `@DynamicInsert`

### 🔹 3. `@DynamicInsert` — 동적 INSERT

```java
@Entity
@DynamicInsert
public class Member {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String username;
    private String email;
    private String address;
}
```

#### ✅ 동작 원리
- Hibernate가 `INSERT` SQL을 생성할 때, **null이 아닌 컬럼만 포함된 INSERT문**을 생성.

#### 예시

```java
Member member = new Member();
member.setUsername("홍길동");
em.persist(member);
```

👉 실행되는 SQL

```sql
INSERT INTO member (username) VALUES ('홍길동');
```

(`email`, `address`가 `null`이면 제외됨)

#### 💡 효과
- DB의 **DEFAULT 값 설정**을 활용 가능
- INSERT 시 **쿼리가 더 짧고 명확**
- 단, **SQL 캐싱이 어렵기 때문에 약간의 성능 저하** 가능(계속 SQL 쿼리가 실행되어서 성능 저하 가능성 O)

### 6️⃣ JPQL과 네이티브 쿼리 비교

| 구분    | JPQL                       | 네이티브 쿼리                  |
| ----- | -------------------------- | ------------------------ |

| 사용 예시 | `"SELECT m FROM Member m"` | `"SELECT * FROM member"` |
- 네이티브 쿼리: SQL 쿼리 사용
