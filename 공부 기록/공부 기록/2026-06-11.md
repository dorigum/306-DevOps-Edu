### 전통적 프로그래밍

```
개발자 → 로직 구현 → 결과 생성
```

- 결정론적
- 결과 예측 가능
- 코드 중심

```
개발자 → AI에게 요청 → 결과 생성
```

- 비결정론적
- 결과가 확률적으로 생성
- 컨텍스트 중심

### AI 개발 패러다임의 진화

```text
전통적 프로그래밍
        ↓
프롬프트 엔지니어링
        ↓
컨텍스트 엔지니어링
        ↓
하네스 엔지니어링
```

결국 AI 시대의 개발자는 **"코드를 작성하는 사람"** 에서 **"AI가 올바르게 동작할 수 있는 환경과 맥락을 설계하는 사람"** 으로 역할이 확장되고 있다.

이는 앞으로 **Spring AI, MCP, Agent, RAG 기반 시스템을 설계하는 개발자에게 가장 중요한 역량**이 될 것이다.

### AI 응용 서비스 아키텍처

![[Pasted image 20260611100112.png]]
이 그림은 **최근 AI 서비스가 어떻게 구성되는지를 보여주는 전형적인 아키텍처**이다.

사용자는 웹 또는 모바일 화면인 **Front-End**를 통해 AI 서비스에 요청을 보낸다.

요청을 받은 **Back-End(Spring AI Agent)** 는 단순히 AI 모델을 호출하는 역할만 하는 것이 아니라, 사용자의 의도를 분석하고 필요한 작업을 판단하는 **AI 오케스트레이터 역할을 수행한다.**

필요한 경우 MCP Server와 같은 **외부·내부 도구(Tool)** 를 호출하여 이메일 전송, 슬랙 알림, 데이터 조회 등의 작업을 수행할 수 있다.

또한 Vector Store나 DBMS와 같은 **기억·지식 저장소** 에서 관련 정보를 검색하여 AI에게 추가 컨텍스트를 제공한다.

이후 Spring AI Agent는 수집한 정보와 사용자의 요청을 함께 AI 모델에게 전달한다.

AI 모델은 OpenAI Chat Model이나 Embedding Model과 같이 확률적으로 답변을 생성하는 역할을 담당한다.

생성된 결과는 다시 Spring AI Agent를 거쳐 후처리된 후 사용자에게 전달된다.

즉, 실제 AI 서비스의 핵심은 AI 모델 자체보다도 **Spring AI Agent가 도구, 데이터, 기억, AI 모델을 어떻게 연결하고 제어하느냐** 에 있다.

그래서 최근 AI 개발의 핵심은 단순한 모델 호출이 아니라 **Agent 기반의 AI 서비스 설계와 컨텍스트 엔지니어링** 이라고 할 수 있다.

Spring AI의 가장 큰 특징은 **LLM 제공업체에 대한 추상화(Abstract Layer)** 를 제공한다는 점이다.

개발자는 OpenAI GPT, Google Gemini, Anthropic Claude, Ollama와 같은 다양한 AI 모델을 사용하더라도 ==**동일한 API와 프로그래밍 방식으로 개발할 수 있다**.==

즉, **애플리케이션은 특정 AI 모델에 직접 의존하지 않고 Spring AI를 통해 AI 서비스를 호출**하게 된다.

따라서 모델 변경이나 멀티 LLM 전략을 적용할 때 애플리케이션 코드를 크게 수정할 필요가 없다.

_**결과적으로**_
**Spring AI는 개발자가 AI 모델 자체보다** ==**비즈니스 로직과 데이터 활용에 집중할 수 있도록 지원하는 AI 통합 프레임워크**==라고 할 수 있다.


### 자동 설정의 3단계 핵심 동작 파이프라인
![[Pasted image 20260611105516.png]]

Spring AI는 S**tarter 의존성이 추가되면 자동 설정(Auto Configuration)이 동작하여 필요한 객체를 자동으로 생성한다.**

첫 번째 단계는 **Starter 탐지**로, 프로젝트에 추가된 Spring AI 라이브러리를 Spring Boot가 자동으로 인식힌다.

두 번째 단계는 **Property 바인딩**으로, application.properties 또는 환경 변수의 설정값을 내부 설정 객체에 매핑한다.

세 번째 단계는 **Bean 등록**으로, ChatModel, EmbeddingModel, VectorStore 등의 객체를 Spring Bean으로 자동 생성한다.

**덕분에 개발자는 복잡한 설정 코드 없이 의존성 추가와 설정만으로 AI 기능을 바로 사용할 수 있다.**

### Prompt 클래스
- `ModelRequest` 인터페이스의 구현체로
	- 복수 개의 SystemMessage
	- 사용자 메시지 UserMessage
	- AI 메시지 AssistantMessage를 저장합니다.
- 그리고 LLM 요청 시, 적용할 수 있는 대화 옵션 ChatOptions를 가지고 있습니다.

![[Pasted image 20260611152613.png]]

Prompt 객체는 Spring AI에서 AI 모델에게 전달할 **메시지와 모델 설정값을 하나로 묶어 관리하는 컨테이너이다.**

내부에는 SystemMessage, UserMessage, AssistantMessage와 같은 대화 컨텍스트 정보가 저장된다.
또한 Temperature, Max Tokens 등의 ChatOptions 설정을 함께 포함하여 AI의 응답 방식을 제어할 수 있다.

즉, Prompt는 "**무엇을 질문할 것인가**"와 "**어떻게 답변받을 것인가**"를 하나의 객체로 캡슐화한 것이다.
Spring AI는 이 Prompt 객체를 ChatModel에 전달하여 최종적으로 AI 모델과 통신을 수행한다.

![[Pasted image 20260611152740.png]]

Spring AI의 Prompt 객체가 단순한 문자열이 아니라 **메시지 목록과 모델 옵션을 함께 관리하는 구조화된 객체**임을 보여준다.

Prompt 내부의 **List`<Message>`** 에는 System, User, Assistant와 같은 역할별 메시지가 저장되어 대화의 컨텍스트를 구성한다.

또한 **ChatOptions**에는 Temperature, Max Tokens 등의 설정값이 포함되어 AI 응답 방식을 제어한다.

따라서 Spring AI에서 프롬프트는 단순한 질문 문장이 아니라, AI가 답변을 생성하는 데 필요한 모든 정보를 담고 있는 요청 객체라고 볼 수 있다.

### Message API
**메시지 역할을 세분화하여 Agent의 페르소나와 행동 지침을 설계**

![[Pasted image 20260611153125.png]]

- - **LLM 요청 이전에 생성되는 메시지 ⇒ `SystemMessage`, `UserMessage`**
- **LLM 요청 이후에 생성되는 메시지 ⇒ `AssistantMessage`, `ToolResponseMessage`**

| 메시지                     | 설명                                                                                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **SystemMessage**       | - 대화 전반에 걸쳐 AI 모델의 행동 방식, 페르소나, 규칙, 제약 사항을 정의하는 데 사용  <br>- 대화의 목표와 규칙을 설정하는 보이지 않는 가이드 역할  <br>- 대화의 가장 중요한 맥락을 설정                             |
| **UserMessage**         | - 사용자(End User)가 AI 모델에게 보내는 실제 요청, 질문, 발언을 나타냄  <br>- 대화의 입력(Input)을 제공하는 역할                                                                   |
| **AssistantMessage**    | - AI 모델이 사용자에게 보낸 응답이나 이전에 생성했던 대화 내용을 나타냄  <br>- 이전 대화의 기억(History)을 구성해 모델이 일관성 있는 응답을 하도록 도움  <br>- 대화의 출력(Output)과 기존 맥락을 구성하는 AI 모델 자체의 역할 |
| **ToolResponseMessage** | - AI 모델이 특정 외부 도구(Tool)나 함수(Function) 사용을 결정하고, 해당 도구의 실행이 완료된 후 그 결과를 담아 다시 모델에게 전달하는 메시지  <br>- AI 모델이 요청한 외부 시스템의 실행 결과를 전달하는 역할             |

### Spring AI에서 Builder 패턴

>객체 생성의 복잡도를 낮추고 코드의 가독성을 극대화하기 위해 거의 모든 핵심 컴포넌트(ChatClient, SearchRequest, Prompt 등)에서 표준으로 사용되는 디자인 패턴이다.
>단순히 객체를 생성하는 것을 넘어, Spring AI의 자동 설정(Auto-configuration)과 결합하여 강력한 유연성을 제공한다.

**Spring AI가 생성자(Constructor) 대신 Builder를 고집하는 이유**

- **가독성 (Fluent API):** 설정할 항목이 많아도 메서드 체이닝을 통해 어떤 값을 설정하는지 명확히 알 수 있다. **불변성 (Immutability):** build()를 통해 생성된 최종 객체는 수정이 불가능한 상태가 되어 멀티스레드 환경에서 안전하다.

- **유연한 커스터마이징** Spring이 미리 만들어준 Builder를 주입받아, 내가 필요한 설정만 살짝 추가해서 객체를 완성할 수 있다.


### ChatOptions 인터페이스

![[Pasted image 20260611154805.png]]

- **ChatOptions**는 AI 모델의 답변 생성 방식과 품질을 제어하는 설정값(하이퍼파라미터) 모음이다.

- **Temperature**는 창의성을 조절하며, 값이 높을수록 다양한 답변을 생성하고 낮을수록 일관되고 결정적인 답변을 생성한다.

- **MaxTokens**는 AI가 생성할 수 있는 최대 응답 길이를 제한하여 과도하게 긴 답변을 방지한다.

- **TopK**와 **TopP**는 다음 단어를 선택하는 범위를 조절하여 답변의 다양성과 자연스러움을 제어한다.

즉, ChatOptions는 AI에게 무엇을 물어볼지보다 **어떤 방식으로 답변하게 할 것인지를 설정하는 중요한 옵션이다.**

## 4. top-k vs top-p 차이 요약

|항목|top-k|top-p (nucleus)|
|---|---|---|
|의미|상위 K개 단어만 후보|누적 확률이 P 이상이 될 때까지의 단어만 후보|
|값 타입|정수 (예: 20, 40, 50)|0 ~ 1 사이 실수 (예: 0.8, 0.9, 0.95)|
|후보 개수|항상 최대 K개 (고정 상한)|상황에 따라 달라짐 (동적)|
|장점|직관적, 구현 간단|상황별로 자연스럽게 후보 수 조절|
|단점|확률 분포가 쏠려 있어도 K개 꽉 채울 수 있음|P 설정이 이해 안 되면 감이 안 올 수 있음|

실무에서는:
- **top_p만 쓰거나, top_k는 꺼두는 경우도 많고**
- 가끔 둘 다 같이 설정해서 “너무 많은 후보/너무 적은 후보”를 동시에 제어하기도 한다.

### ChatModel API의 사용 흐름

[https://docs.spring.io/spring-ai/reference/api/chatmodel.html#_chat_options](https://docs.spring.io/spring-ai/reference/api/chatmodel.html#_chat_options)


![[Pasted image 20260611160109.png]]이 그림은 Spring AI가 ChatOptions를 적용하여 AI 모델과 통신하는 전체 처리 과정을 보여준다.

먼저 애플리케이션 시작 시 설정된 **기본 ChatOptions**가 ChatModel에 등록되고, 요청 시 Prompt 객체에 포함된 **런타임 ChatOptions**가 함께 전달된다.

Spring AI는 두 옵션을 병합(Merge)하여 최종 대화 옵션을 결정하며, 동일한 설정이 있을 경우 런타임 옵션이 우선 적용된다.

이후 Prompt와 ChatOptions를 각 AI 모델이 이해할 수 있는 네이티브 요청 형식으로 변환하여 OpenAI, Gemini, Ollama 등의 모델에 전달한다.

마지막으로 AI 모델의 응답을 Spring AI 표준 형식인 **ChatResponse** 객체로 변환하여 애플리케이션에 반환한다.
