# Spring Security
스프링FW 기반의 어플리케이션 보안(인증과 인가, 보안조치)을 담당하는 프레임워크

- 회원가입부터 로그인, 로그아웃, 세션 관리, 권한 관리까지 온라인 플랫폼에 맞춰 다양하게 작업되는 기능을 효과적으로 지원하기 위해 개발된 것이 Spring Security로 개발자들이 보안 관련 기능을 효율적이고 신속하게 구현할 수 있도록 도와준다.

- **사이트에 대해서 유효한 사용자인지 확인하는 것이 인증(로그인)** 이고,
- **인증된 사용자가 사용 할 수 있는 기능인지 확인하고 권한이 부여된 리소스에만 접근을 허용하는 과정을 인가**라고 한다.

- Spring Security는 기본적으로 인증 절차를 거친 후에 인가 절차를 진행하게 되며, 인가 과정 에서 해당 리소스에 대한 접근 권한이 있는지 확인하고 접근을 허용하게 된다.

- 인증, 인가를 위해 Principal을 아이디로 Credential을 비밀번호로 사용하는 Credential 기반의 인증 방식을 사용한다.
	- **Principal(접근 주체)** : 보호 받는 리소스에 접근하는 대상
	- **Credential(비밀번호)** : 리소스에 접근하는 대상의 비밀번호

### ==[Spring Security 특징]==
- 스프링 시큐리티는 **필터(Filter)를 기반으로 동작**하기 때문에 스프링 MVC와 분리되어 관리 및 동작한다.
- **필터(Filter)는 서블릿(DispatcherServlet)으로 가기 전에 적용됨으로 가장 먼저 URL 요청을 받는다.**
- **==세션&쿠키** 방식==으로 인증을 처리한다.
- 스프링의 ==DispatcherServlet 앞단에 다양한 역할의 Filter==로 구성되어 있다.
- DispathcerServlet으로 넘어가기 전에 이 Filter가 요청을 가로채서 클라이언트의 리소스 접근 권한을 확인하고 없는 경우에는 인증 요청 화면으로 자동으로 리다이렉트 한다.
- 내장된 인증 과정은 폼로그인(/login)이다.
- /logout 으로 요청하고 내장된 로그아웃도 제공한다.

- 오픈소스 프레임워크로 보편적인 **인증, 인가, UI 처리(Security UI 제공)** 에 대한 기본 구현을 제공하고 있으며, 일부를 변경할 수 있게 확장이 가능
- 프로그래머는 처음부터 인증과 권한을 위한 코드를 만들기 보다는 스프링 시큐리티가 제공하는 틀을 ==재사용==하고, 필요한 부분만 ==커스텀마이징==함으로써 보다 빠르게 인증과 권한 부분을 구현할 수 있다.
- **암호화 기능도 제공**하여 암호화 기능에 대한 특별한 제약이 없다면, 스프링 시큐리티가 제공하는 암호화 기능을 사용해서 비밀번호, 결제 정보 등을 암호화할 수 있다.
- **in-Memory 기능 제공**
	- 관리자처럼 1~2명 정도의 데이터라면 미리 Role을 설정해서 세팅 가능
- **CSRF 공격 방어 가능**

### 용어
- 접근 주체(Principal) : 보호된 대상에 접근하는 사용자 객체
- 인증(Authentication) : 증명, 유저가 누구인지 확인하는 것, 회원가입하고 로그인하는 것
- 인가(Authorization) : 허락, 유저에 대한 권한을 확인, 허락하는 것
