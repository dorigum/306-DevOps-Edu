## 고가용성(High Availability, HA)
- 시스템이 장애가 나더라도 서비스가 가능한 한 중단되지 않고 계속 동작할 수 있도록 하는 성질
- **목표**
	- 서비스 다운타임 최소화
	- 장애 발생 시 자동 복구(Failover)
	- 이중화(Replication, Clustering) 등을 통한 안정성 확보
- **예시**
	- DB 서버를 한 대만 두면 그 서버가 다운되면 서비스 전체가 멈춤
	- 따라서 여러 대(DB Cluster)를 두고, 한 대가 죽으면 다른 대가 즉시 대신 동작하도록 구성.
		- 즉, **“항상 켜져 있는 서비스”** 를 만들기 위한 전략이다.


## ✅트레이드 오프(Trade-off, 상충관계)

- ==하나를 얻기 위해 다른 하나를 희생해야 하는, 양립할 수 없는 선택 상황==을 의미
- 효율이나 성능을 높이면 비용이나 품질이 낮아지는 식의 이율배반적 관계
- 자원이 제한된 상황에서 **최적의 균형(Trade-off)을 찾는 의사결정의 핵심 개념**

- **핵심 특징 및 사례**
	- **경제/정책:** 실업률을 낮추면 물가가 상승하는 필립스 곡선 관계
	- **비즈니스:** 원가 절감(비용)을 위해 품질(서비스)을 낮추는 경우
	- **엔지니어링/IT:** 시스템의 성능(속도)을 높이기 위해 용량(저장 공간)을 희생하거나, 보안을 강화하면 편리함이 감소하는 경우
	- **머신러닝:** 편향(Bias)을 낮추면 분산(Variance)이 증가하는 데이터 모델의 상충 관계

## # **단방향 데이터 흐름(One-way Data Flow)** 원칙

> 자식 컴포넌트는 props를 “읽기만” 할 수 있고 직접 수정할 수 없다.
> 즉, 자식은 이렇게 하면 안 된다.

```jsx
props.value = 10;  // ❌ 불가능! 오류
```

React에서는 props를 **읽기 전용(read-only)** 으로 취급한다.


---
### 왜 props를 수정할 수 없게 했을까? (중요한 React 철학)

### ▶ 이유 1: **단방향 데이터 흐름(One-way Flow)**

React에서는 “데이터는 부모 → 자식 방향으로만 흐른다.”

만약 자식이 props를 마음대로 바꿀 수 있다면:

- 상태 흐름이 꼬이고
- 디버깅이 매우 어려워지고
- React의 재렌더링 구조가 깨진다

그래서 React는 props를 **불변(immutable)** 으로 한다.


---
# props는 불변(immutable).

즉, 아래는 절대 불가능:

```jsx
props.count++;       // ❌
props.name = "John"; // ❌
```


---
## 그렇다면 자식이 부모의 값을 바꾸고 싶으면?

직접 수정은 불가능하지만 → **부모에게 “수정 요청”을 보내는 방식이 정석**이다.

## ✔ 부모가 setter 함수를 props로 내려주고

```jsx
function Parent() {
  const [count, setCount] = useState(0);

  return <Child count={count} setCount={setCount} />;
}

```

## ✔ 자식은 props로 받은 함수를 호출한다

```jsx
function Child({ count, setCount }) {
  return (
    <button onClick={() => setCount(count + 1)}>
      증가
    </button>
  );
}
```

### → 이렇게 “부모의 상태를 변경하는” 것은 가능

### → 하지만 “props 자체를 수정하는 것”은 절대 불가능


---
## 정리

|구문|가능 여부|이유|
|---|---|---|
|`props.value = 10`|❌ 불가능|props는 읽기 전용|
|`props.setValue(10)` 같이 부모가 준 함수 호출|⭕ 가능|부모에게 변경 요청|
|자식이 state를 들고 있다가 부모로 전달|⭕ 가능|상태 전달은 props 이용|

> 자식 컴포넌트는 props를 수정할 수 없다. 하지만 “부모가 내려준 함수(props)”를 호출하여 부모 state를 변경할 수는 있다.
