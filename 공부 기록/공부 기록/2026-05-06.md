# Spring 탄생 배경
### 자바 엔터프라이즈 개발의 혼돈 (2000년대 초반)

한때 자바로 기업용 웹 애플리케이션을 개발하는 가장 주된 방법은 **J2EE(Java 2 Platform, Enterprise Edition)** 였다.

하지만 이 기술을 사용하면서 느끼는 **문제점** 있었다.

- 개발자들은 **EJB(Enterprise JavaBeans)** 라는 복잡한 컴포넌트를 써야 했고,
- 단순한 로직도 **무거운 설정과 클래스**들로 둘러싸여 있었고
- 테스트도 어려웠고, 유지보수도 너무나 힘들었다.

> 🧠 "여러분이라면 단순한 게시판을 만들기 위해 수십 개의 클래스를 작성하고, 복잡한 배포 과정을 거친다면… 어떻게 느끼겠어요?"

개발자들은 점점 지쳐가기 시작했다.

### 변화의 씨앗 - “경량 프레임워크”의 등장

**2002년**, 한 개발자 커뮤니티에 **Rod Johnson**이라는 호주 출신의 개발자가 **한 권의 책을 낸다**.

책 제목: _**"Expert One-on-One J2EE Design and Development"**_

이 책에서 그는 이렇게 말한다.

> **“EJB 없이도 충분히 강력하고, 더 깔끔한 애플리케이션을 만들 수 있다.”**

그리고 부록에 **자신이 만든 작은 프레임워크**를 실었다.

그게 바로…

> 🐣 **Spring Framework의 초기 버전**

### 이름의 유래와 철학

**"Spring"** — 봄이라는 이름은 이런 의미를 담고 있다.

- 겨울 같은 무거운 J2EE의 시대는 가고,
- 개발자에게 따뜻하고 가벼운 “개발의 봄”이 오기를 바란다.

> 🎯 핵심 철학: **"복잡한 것을 단순하게(Simple is better than complex)"**

### Spring의 컨셉 – 왜 특별했을까?

Spring은 기존 J2EE의 문제를 해결하기 위해 다음과 같은 **핵심 개념을 도입**했다.

| 개념                    | 설명                                                      |
| --------------------- | ------------------------------------------------------- |
| **IoC (제어의 역전)**      | 객체 생성과 의존성 주입을 개발자가 아닌 컨테이너가 담당                         |
| **DI (의존성 주입)**       | 구성요소 간 결합도를 낮춰 유연한 구조 제공                                |
| **AOP (관점 지향 프로그래밍)** | 공통기능(로깅, 트랜잭션 등)을 핵심 비즈니스 로직과 분리                        |
| **POJO 기반 개발**        | EJB처럼 무거운 제약 없이 평범한 자바 객체(Plain Old Java Object)로 개발 가능 |
이 모든 것을 통해 개발자는 **테스트하기 쉽고, 재사용 가능한, 유지보수성 높은 코드를 작성**할 수 있게 됐다.

### 점진적인 진화 - Spring Boot의 등장

Spring은 시간이 흐르면서 강력해졌지만, 설정이 너무 많고 복잡하다는 지적도 받았다.

그래서 **Spring Boot(2014)가 등장!**

- ==**설정 자동화 (Auto Configuration)**==
- ==**내장 서버 (Tomcat 내장)**==
- ==**의존성 관리 (starter 패키지)**==

> 📦 즉, “**Spring은 강력하지만 어렵다” → “Spring Boot는 강력한 Spring을 쉽게 쓰게 한다**!”

### 🎓 우리는 왜 Spring을 배워야 할까?

- Spring은 **전 세계 수백만 개발자가 사용하는** 표준 프레임워크.
    
- 기업의 대규모 서비스부터 스타트업의 빠른 MVP(***Minimum Viable Product*-최소 실행 가능한 제품) 개발까지 활용.
    
    - **MVP란?**
        MVP는 '최소 기능 제품(Minimum Viable Product)'의 약자로, **제품의 핵심 기능만 갖춘 최소한의 시제품**을 뜻한다. 이는 완벽한 제품을 만들기보다 빠르게 시장에 출시하여 고객의 반응을 통해 아이디어를 검증하고, 얻은 피드백을 바탕으로 제품을 개선해 나가는 개발 방법론.
        
- 특히 **Spring Boot**와 **Spring Cloud**는 **마이크로서비스 아키텍처(MSA)** 시대에 더욱 중요해지고 있다.
