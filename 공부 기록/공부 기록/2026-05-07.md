# Spring에서 **객체(Bean)를 생성하고 주입(DI)하는 데 사용되는 주요 어노테이션**

## 1. 전체 분류 개요

| 분류             | 대표 어노테이션                                                                          | 설명                  |
| -------------- | --------------------------------------------------------------------------------- | ------------------- |
| **Bean 생성 관련** | `@Component`, `@Service`, `@Repository`, `@Controller`, `@Bean`, `@Configuration` | 객체를 Spring 컨테이너에 등록 |
| **의존성 주입(DI)** | `@Autowired`, `@Inject`, `@Resource`, `@Qualifier`, `@Value`                      | 의존 객체를 주입           |
## 2. Bean 생성 관련 어노테이션
### 1) `@Component` `// <bean class="" id=""/> 동일`
- POJO 클래스를 **Bean으로 등록**
- 기본 이름 - 클래스 이름의 camelCase (`UserService` → `userService`)

```java
@Component
public class UserService { ... }
```

### 2) `@Service`, `@Repository`, `@Controller`
- `@Component`의 **세부 역할별 세분화**
- 역할에 따라 구분하여 사용하는 것이 Spring 철학에 맞음

| 어노테이션         | 용도                           |
| ------------- | ---------------------------- |
| `@Service`    | 비즈니스 로직 처리 클래스               |
| `@Repository` | DB 접근 클래스 (DAO), 예외 변환 기능 포함 |
| `@Controller` | 웹 요청 처리 클래스 (Spring MVC 전용)  |

```java
@Service
public class OrderService { ... }

@Repository
public class OrderRepository { ... }

@Controller
public class OrderController { ... }
```

### 3) `@Bean`
- **Java Config 클래스에서 수동으로 Bean 등록**할 때 사용

```java
@Configuration
public class AppConfig {
    @Bean
    public UserService userService() {
        return new UserService();
    }
}
```

---
## 3. 의존성 주입(DI) 관련 어노테이션
### 1) `@Autowired`
- Spring의 기본 DI 어노테이션
- 타입(Type) 기반으로 의존성 자동 주입(동일한 타입 여러 개 인 경우 byName기반)
- 필드, 생성자, 세터 모두에 사용 가능

```java
@Autowired
private UserRepository userRepository;
```

```java
@Autowired
public UserService(UserRepository repo) {
    this.userRepository = repo;
}
```

### 2) `@Qualifier`
- **동일 타입의 Bean이 여러 개 있을 경우** 어떤 Bean을 주입할지 이름으로 지정

```java
@Autowired
@Qualifier("mainUserRepository")
private UserRepository userRepository;
```

### 3) `@Inject` (JSR-330)
- Java 표준 어노테이션, 기능은 `@Autowired`와 동일
- Spring에서 지원되나, Spring 전용 기능(@Qualifier 등)을 쓰려면 `@Autowired`가 더 나음

- **JSR이란**?
  ### JSR의 의미
- **JSR**은 **Java Specification Request**의 약자
- 즉, “Java 표준 명세 요청서”라는 뜻으로, Java의 표준 기능을 정의할 때 JCP (Java Community Process)를 통해 제안된 문서이다.
	- 예:
		- JSR-330 → `@Inject` (Dependency Injection for Java)
		- JSR-303 → `@Valid`, `@NotNull` 등 Bean Validation
		- JSR-250 → `@Resource`, `@PostConstruct`, `@PreDestroy` 등

```java
@Inject
private UserRepository userRepository;
```

### 4) `@Resource` (JSR-250)
- 이름 기반 주입 (기본적으로 **Bean 이름**으로 주입)
- `name` 속성을 명시하지 않으면 필드명으로 주입

```java
@Resource(name = "userRepository")
private UserRepository repo;
```

### 5) `@Value`
- 프로퍼티 값, 상수 값 등 단순 값 주입

```java
@Value("${server.port}")
private int port;
```

## 🧠 정리 표
|역할|어노테이션|설명|
|---|---|---|
|Bean 생성|`@Component`|일반 객체 등록|
|Bean 생성|`@Service`|비즈니스 로직용 컴포넌트|
|Bean 생성|`@Repository`|DAO 클래스, 예외 변환 지원|
|Bean 생성|`@Controller`|Spring MVC용 컨트롤러|
|Bean 생성|`@Configuration` + `@Bean`|Java 기반 수동 등록|
|DI|`@Autowired`|Spring 기본 의존성 주입|
|DI|`@Qualifier`|이름으로 주입 Bean 지정|
|DI|`@Inject`|JSR-330, 표준 자바 DI|
|DI|`@Resource`|이름 기반 DI (JSR-250)|
|DI|`@Value`|단일 값 또는 프로퍼티 주입|

---
- `@Component` 계열은 **스캔 방식 자동 등록**
- `@Bean`은 **명시적 수동 등록**
- 주입 시에는 `@Autowired`가 가장 널리 쓰이며, **생성자 주입이 권장됨**
- ==**Spring Boot에서는 기본으로 @ComponentScan + @Configuration이 적용되어 있음**==

# Lombok 라이브러리
## 1. Lombok이란 무엇인가?
> Lombok은 Java 코드의 보일러플레이트(boilerplate) 코드를 자동으로 생성해주는 라이브러리.

즉, Getter, Setter, 생성자, `toString()`, `equals()`, `hashCode()` 등을 **어노테이션 한 줄로 자동 생성**해주는 도구이다.

---
## 2. 왜 Lombok이 필요한가?
기존의 Java 클래스는 단순 데이터 객체를 만들 때에도 너무 많은 반복 코드가 필요함

```java
public class User {
    private String name;
    private int age;

    public User() {}
    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }

    @Override
    public String toString() {
        return "User{name='" + name + "', age=" + age + "}";
    }
}
```

➡️ 이렇게 반복적인 코드를 줄이기 위해 등장한 것이 **Lombok이다.**

---
## 🔷 3. Lombok 주요 어노테이션
|어노테이션|설명|
|---|---|
|`@Getter` / `@Setter`|모든 필드의 getter, setter 자동 생성|
|`@ToString`|`toString()` 자동 생성|
|`@EqualsAndHashCode`|`equals()` 및 `hashCode()` 자동 생성|
|`@AllArgsConstructor`|모든 필드를 매개변수로 받는 생성자 생성|
|`@NoArgsConstructor`|기본 생성자 생성|
|`@RequiredArgsConstructor`|`final` 또는 `@NonNull` 필드만 생성자 매개변수로 생성|
|`@Data`|위의 대부분을 한 번에 적용 (`Getter`, `Setter`, `ToString`, `EqualsAndHashCode`, `RequiredArgsConstructor`)|
|`@Builder`|빌더 패턴 자동 생성 (객체 생성 시 가독성 ↑)|

---
## 4. Lombok 사용법

### ✅ (1) 의존성 추가

**Maven**

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <version>1.18.34</version> <!-- 최신 버전 사용 -->
    <scope>provided</scope>
</dependency>
```

**Gradle**

```groovy
implementation 'org.projectlombok:lombok:1.18.34'
annotationProcessor 'org.projectlombok:lombok:1.18.34'
```

> ⚠️ ==**IDE(예: IntelliJ, Eclipse)에서도 Lombok 플러그인을 설치해야 인식된다.**==

---
### ✅ (2) 예제 코드

```java
import lombok.Data;
import lombok.Builder;

@Data
@Builder
public class User {
    private String name;
    private int age;
}

```

사용 예시 👇

```java
public class Main {
    public static void main(String[] args) {
        User user = User.builder()
                        .name("홍길동")
                        .age(25)
                        .build();

        System.out.println(user.getName());  // 홍길동
        System.out.println(user);            // User(name=홍길동, age=25)
    }
}

```

> ➡️ 코드가 매우 간결해지고, 생성자/Getter/Setter를 일일이 작성할 필요가 없다.

## 5. Lombok의 장점
| 장점                           | 설명                          |
| ---------------------------- | --------------------------- |
| ✅ **보일러플레이트 코드 제거**          | getter/setter, 생성자 등을 자동 생성 |
| ✅ **가독성 향상**                 | 핵심 로직에 집중할 수 있음             |
| ✅ **빌더 패턴 지원**               | 복잡한 객체 생성 시 가독성 높음          |
| ✅ **생산성 향상**                 | 클래스 작성 속도 빨라짐               |
| ✅ **JPA, Spring Boot 등과 호환** | 엔티티, DTO, 서비스 등 어디서든 사용 가능  |

---
## 6. Lombok의 단점
|단점|설명|
|---|---|
|⚠️ **IDE 의존성**|Lombok 플러그인이 없으면 코드 인식 불가 (컴파일 에러처럼 보임)|
|⚠️ **컴파일 시 코드 생성**|런타임에는 실제로 코드가 보이지 않아 디버깅이 어려움|
|⚠️ **불변 객체 아님**|`@Data`는 `Setter`를 자동 생성하므로, 의도치 않게 mutable 객체가 됨|
|⚠️ **표준 문법 아님**|Java 언어 표준이 아니라 외부 라이브러리에 의존|
|⚠️ **record로 대체 가능**|Java 16 이상에서는 `record`로 대체 가능 (단, 불변 데이터 전용에 한함)|

---
## 7. Lombok vs record 비교
| 항목       | Lombok           | record             |
| -------- | ---------------- | ------------------ |
| 코드 자동 생성 | ✅ 다양한 어노테이션으로 가능 | ✅ 기본 생성자/메서드 자동 생성 |
| 불변성      | ❌ 기본적으로 가변       | ✅ 불변(immutable)    |
| 상속       | ✅ 가능             | ❌ 불가능              |
| 표준 여부    | ❌ 외부 라이브러리       | ✅ JDK 표준           |
| JPA 엔티티  | ✅ 완벽 지원          | ❌ 비권장              |
| DTO, VO  | ✅ 가능             | ✅ 더 적합             |

---
## 8. 정리 요약

> 💡 Lombok은 "**생산성 향상을 위한 코드 자동 생성 도구**"이며,
> 
> **record는 "불변 데이터 객체를 위한 표준 문법"이다.**

👉 Lombok은 **모든 계층(class, entity, DTO)** 에서 활용할 수 있지만,
👉 record는 **데이터 전달용 DTO/VO**에 특화되어 있다.

---
### 한 줄 요약

> Lombok은 자바의 반복 코드를 자동으로 생성해주는 생산성 향상 라이브러리이며,
> 
> **장점**은 코드 간결성과 생산성,
> **단점**은 IDE 의존성과 표준 아니다.
