## MCP(Model Context Protocol)
#### Function Calling → Tool Calling → MCP 진화 과정

#### 1. Function Calling
>**"AI에게 행동할 수 있는 손을 쥐어주다"**

초기 LLM은 학습된 데이터를 기반으로 답변을 생성할 수는 있었지만, 외부 시스템과 상호작용하는 행동은 할 수 없었다.

예를 들어,
- 실시간 날씨 조회
- 이메일 발송
- 데이터베이스 조회 및 수정
- 외부 API 호출

과 같은 작업은 수행할 수 없었다.

이 문제를 해결하기 위해 등장한 것이 **Function Calling이다.**


#### 2. Tool Calling
>**"한 번에 여러 도구를 유연하게 다루다"**

Tool Calling은 Function Calling이 발전한 형태이다.

Function Calling이 단순히 "함수(Function)"를 호출하는 개념이었다면,

Tool Calling은 더 넓은 범위의 "도구(Tool)"를 사용할 수 있도록 확장되었다.


#### 3. MCP (Model Context Protocol)
>**"파편화된 도구들을 하나로 연결하는 표준"**

Tool Calling이 등장하면서 새로운 문제가 발생했다.

각 플랫폼마다 Tool을 연결하는 방식이 달랐던 것이다.

예를 들어 Notion 연동 Tool을 만들었다고 가정하면
- OpenAI
- Anthropic
- LangChain
- Spring AI
- Claude Desktop

각 환경마다 별도의 연동 코드를 작성해야 했다.


#### MCP의 등장
- 이 문제를 해결하기 위해 Anthropic이 제안한 개방형 표준이 **MCP(Model Context Protocol)** 이다.
- MCP는 AI 모델과 외부 도구 간의 통신 규격을 표준화한다.

#### MCP의 역할
MCP를 사용하면 AI는 표준 방식으로 다양한 시스템과 연결할 수 있다.

**예시**
- GitHub
- Slack
- Notion
- Database
- Google Drive
- File System
- Email

## MCP(Model Context Protocol)

### MCP가 필요한 이유?
초기의 LLM 애플리케이션 구조는

```
사용자 입력 → 프롬프트 구성 → 모델 호출 → 응답 출력
```

### AI 에이전트의 기술적 진화

![[Pasted image 20260616094037.png]]

현재의 LLM은 뛰어난 언어 이해 능력을 가지고 있지만 **두 가지 한계**가 있다.

첫 번째는 **지능의 한계** 로, 학습이 끝난 시점 이후의 최신 정보나 실시간 데이터에 직접 접근할 수 없다.

두 번째는 **행동의 부재**로, 스스로 이메일을 보내거나 데이터베이스를 수정하는 등의 실제 작업을 수행할 수 없다.

**이러한 한계를 해결하기 위해** LLM은 외부 시스템과 연결되어 최신 정보를 조회하고 필요한 작업을 실행해야 한다.

바로 이 역할을 담당하는 것이 **MCP(Model Context Protocol)**이며, **AI가 다양한 외부 도구와 안전하게 연결될 수 있도록 해주는 표준 인터페이스**이다.

[What is the Model Context Protocol (MCP)? - Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)

[![](https://www.elastic.co/apple-touch-icon.png)elastic모델 컨텍스트 프로토콜(MCP)이란 무엇일까요?](https://www.elastic.co/kr/what-is/mcp)​

![[Pasted image 20260616094221.png]]

- USB-C가 다양한 기기를 하나의 표준 포트로 연결하듯이, MCP는 AI 모델과 외부 데이터·도구를 하나의 표준 프로토콜로 연결하는 AI 시대의 USB-C이다.
- 왼쪽의 USB-C는 노트북, 스마트폰, 모니터처럼 서로 다른 기기들을 하나의 표준 포트로 연결하는 역할을 한다. 제조사가 달라도 USB-C 규격만 지원하면 동일한 방식으로 연결할 수 있다
- 오른쪽의 MCP도 이와 같은 개념이다. AI 모델과 문서, 데이터베이스, GitHub, Slack, 분석 시스템 등 다양한 외부 데이터와 도구를 하나의 표준 규격으로 연결힌다.
- 과거에는 AI 모델마다 도구를 연결하는 방식이 달라 각각 별도의 개발이 필요했지만, MCP가 등장하면서 하나의 표준 인터페이스를 통해 다양한 시스템을 재사용할 수 있게 되었다.
- 즉, USB-C가 기기 간의 **물리적 연결 표준**이라면, MCP는 AI와 외부 시스템 간의 **의미적(Semantic) 연결 표준**이라고 볼 수 있다.
- 결론적으로 MCP는 AI가 다양한 데이터와 도구를 자유롭게 활용할 수 있도록 하는 **AI 시대의 범용 연결 규격이다.**

![[Pasted image 20260616094257.png]]

이 그림은 MCP(Model Context Protocol)를 이용하여 AI가 외부 시스템과 연결되는 전체 구조를 보여준다.

1. 오른쪽의 **Claude, OpenAI, Cursor와 같은 AI 애플리케이션**은 **MCP Host** 역할을 수행한다.
2. MCP Host 내부에는 각 MCP Server와 통신하기 위한 **MCP Client**가 존재하며, 그림의 `client.py`가 그 예시이다.
3. MCP Client는 표준화된 MCP 프로토콜을 사용하여 Gmail, Slack, Google Calendar, 로컬 파일 시스템과 같은 **MCP Server**에 연결한다.
4. 각 MCP Server는 자신이 담당하는 서비스의 기능을 Tool 형태로 제공하며, AI는 이를 통해 이메일 전송, 일정 조회, 파일 검색 등의 작업을 수행할 수 있다.
5. 즉, MCP는 AI와 외부 서비스 사이를 연결하는 **USB-C 포트와 같은 표준 인터페이스** 역할을 하여, 어떤 서비스든 동일한 방식으로 연결하고 사용할 수 있게 해준다.

### MCP(Model Context Protocol) 주요 핵심 요소

MCP는 AI 애플리케이션이 외부 도구, 데이터, 서비스와 표준 방식으로 연결될 수 있도록 만든 프로토콜

MCP 구조는 크게 **Host, Client, Server 3가지 구성 요소**로 이루어진다.


---
### 1. MCP Host
#### 정의

AI 애플리케이션의 중심 역할을 수행하며, **하나 이상의 MCP Client를 관리하고 조정하는 주체**이다.

#### 역할

- 사용자 요청을 받음
- 연결된 MCP Server 목록 관리
- 각 MCP Server에 대한 MCP Client 생성
- 어떤 MCP Server를 사용할지 결정
- MCP Server로부터 받은 결과를 AI에게 전달

#### 대표 예시

- Claude Desktop
- Claude Code
- **Spring AI 기반 Agent 애플리케이션**
- ChatGPT 기반 Agent

#### 특징

- 여러 MCP Server와 동시에 연결 가능
- 각 MCP Server마다 별도의 MCP Client 생성
- 사용자는 Host만 사용하며 Server를 직접 다루지 않음

#### 구조 예시

```TEXT
사용자
   │
   ▼
MCP Host
 ├── MCP Client A ── MCP Server A
 ├── MCP Client B ── MCP Server B
 └── MCP Client C ── MCP Server C
```


---
### 2. MCP Client

#### 정의

MCP Server와 1:1 연결을 담당하는 통신 라이브러리이다.

#### 역할

- MCP Server와 연결 생성
- 연결 상태 유지
- Tool 목록 조회
- Resource 목록 조회
- Prompt 목록 조회
- Tool 호출 요청 전송
- 응답 수신 후 Host에게 전달

#### 특징

- **하나의 Client는 하나의 Server만 담당**
- Host 내부에서 동작
- Server와의 통신을 추상화

#### 동작흐름

```TEXT
MCP Host
    │
    ▼
MCP Client
    │
    ▼
MCP Server
```

즉, Host는 직접 Server와 통신하지 않고 항상 Client를 통해 통신한다.


---
### 3. MCP Server
#### 정의

AI가 필요로 하는 데이터와 기능(Tool)을 제공하는 프로그램이다.

#### 역할

- Tool 제공
- Resource 제공
- Prompt 제공
- 외부 시스템 연동
- 데이터 조회 및 처리

#### 예시

- 이메일 전송 서버
- Slack 메시지 전송 서버
- GitHub 조회 서버
- Database 조회 서버
- 파일 시스템 서버
- Jira 서버
- Notion 서버


---
### MCP Server 실행 위치
**MCP Server는 실행 위치에 따라 크게 두 가지로 구분된다.**

#### 1) Local MCP Server

동일한 컴퓨터에서 실행되는 MCP Server

#### 특징

- Host와 같은 PC에서 실행
- **STDIO(Standard Input/Output) 방식 사용**
- 설치와 테스트가 간단
- 개발 및 학습 환경에서 주로 사용

#### 예시

```TEXT
Claude Desktop
      │
      ▼
File System MCP Server
(내 PC에서 실행)
```

#### 2) Remote MCP Server
**네트워크를 통해 원격지에서 실행되는 MCP Server**

### 특징

- **별도 서버에서 실행**
- HTTP 기반 통신
- 여러 사용자가 동시에 사용 가능
- 운영 환경에서 주로 사용

### MCP 전체 구조
```TEXT
사용자
   │
   ▼
AI Application
(MCP Host)
   │
   ├── MCP Client
   │         │
   │         ▼
   │    Email MCP Server
   │
   ├── MCP Client
   │         │
   │         ▼
   │    Slack MCP Server
   │
   └── MCP Client
             │
             ▼
       GitHub MCP Server
```


### 한눈에 정리

| 구성요소       | 역할                    | 예시                                           |
| ---------- | --------------------- | -------------------------------------------- |
| MCP Host   | 전체 MCP 환경 관리 및 조정     | Claude Desktop, Claude Code, Spring AI Agent |
| MCP Client | MCP Server와 1:1 연결 담당 | MCP SDK 내부 Client                            |
| MCP Server | 데이터와 기능(Tool) 제공      | Email, Slack, GitHub, DB 서버                  |

#### 핵심 기억 포인트

- **Host = 관리자**
- **Client = 통신 담당자**
- **Server = 기능 제공자**
- **Client와 Server는 1:1 연결**
- **Host는 여러 Client를 통해 여러 Server를 사용할 수 있음**
- **Server는 로컬(STDIO) 또는 원격(HTTP) 환경에서 실행 가능**

![[Pasted image 20260616100315.png]]

```TEXT
**stdio 방식** → MCP Server를 별도 웹 서버로 띄우지 않는다. → Spring AI가 MCP Server 프로세스를 직접 실행한다.

**SSE 방식** → MCP Server를 별도 애플리케이션으로 실행한다. → HTTP를 통해 연결한다.
```

### LLM이 MCP Server를 사용하는 흐름

![[Pasted image 20260616100353.png]]

① MCP Host가 LLM에게 질문을 할 때, 현재 연결되어 있는 MCP Server의 도구 목록을 프롬프트에 실어LLM 에게 전달한다.

② LLM은 학습하지 않은 정보가 필요하거나, 어떤 조치가 필요할 때, MCP Host가 보낸 도구 목록 중에서 호출 가능한 것이 있는지 확인하고 MCP Host 에게 도구 호출 요청을 보낸다.

③ MCP Host는 LLM 요청에 따라 MCP Client를 통해 MCP Server가 가지고 있는 외부 도구를 호출하고 결과를 받는다.

④ MCP Host는 도구 호출 결과를 LLM에게 전달한다.

⑤ LLM은 도구 호출 결과를 취합해서 최종 답변을 MCP Host로 보낸다.


### MCP 를 이용한 외부 도구 호출 흐름

LLM은 직접 외부 시스템에 접근하지 않는다. Spring AI가 **“오케스트레이터“** 역할을 수행하여 도구 실행을 중재한다.
