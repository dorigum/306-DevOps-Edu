	- `useState` 사용하는 이유? -> 자동으로 리랜더링 해주기 때문!

	- 화면 업데이트를 빠르게 할 수 있음 -> 가상 DOM
- 리액트 개발 도구 vite 기본 구조
	- index.html 먼저 찾음 -> main.jsx -> App component 실행
- useEffect 역할
	- 하나의 컴포넌트 라이프사이클을 관리(mount, unmount 될 때 해야 할 일을 제어)
	- dependency 변수가 변경될 때만 상태가 결정됨............
- useEffect 사용 시 자원 해지 방법
	- return -> callback 함수 반환(unmount 될 때), clean
- 컴포넌트 리랜더링 되는 경우
	- state가 변경될 때
	- props 변경될 때
	- 부모의 컴포넌트가 변경될 때
- 최적화, 성능 개선
	- 리랜더링 줄이기...
- useRef, useState의 차이
	- useRef는 리랜더링하지 X, 내부에서만 상태 관리
- 메모이제이션할 때 사용하는 hooks? -> `useMemo`, `useCallback`
- 반복 계산할 때 리랜더링
	- `useMemo()` : **"이 연산, 다시 계산할 필요 있어?"**
		- useMemo는 메모이즈된 값을 return하는 **hook**이다.
		- 인자로 함수와 의존 값(dependencies)을 받는다. useMemo는 두번째 인자로 준 의존 인자 중에 하나라도 변경되면 값을 재 계산한다. 이를 통해 매 렌더 시마다 소요되는 불필요한 계산을 피할 수 있다. 만약 dependencies 인자로 아무것도 전달되지 않는다면, 렌더 시마다 항상 값을 새롭게 계산하여 return한다.
		- useMemo는 hook이기 때문에 오직 **함수형 컴포넌트** 안에서만 사용 가능
		- **리렌더링 될 때마다 불필요한 계산이 발생하는 경우**
		- 예를 들어, **무거운 배열 연산(정렬, 필터링, 맵핑)** 등이 있는 경우.
		
	- React.memo와 useMemo 모두 props가 변하지 않으면(이전 props와 동일하면) 인자로 넘긴 함수는 재실행되지 않고, 이전의 메모이즈된 결과를 반환한다는 점에서 공통점이 있다.
	
	- `React.memo()` : **" 이 컴포넌트, 다시 렌더링할 필요 있어? "**
		- React.memo는 고차 컴포넌트(HOC)
		- React.memo는 HOC이기 때문에 클래스형 컴포넌트, 함수형 컴포넌트 모두 사용 가능
		- **부모 컴포넌트가 리렌더링될 때, 자식 컴포넌트도 불필요하게 렌더링 되는 경우**
		- props가 자주 바뀌지 않는 **정적인 컴포넌트**
- 컴포넌트 기억 -> `useState()
- props 기억 -> `useCallback()`
- 컨텍스트 -> 최상위에 선언하면 props를 전달하지 않고도 사용
	- 단점: 부모 쪽에 있는 데이터가 변경되면 계속 리랜더링 반복
	- 이를 해결하기 위한 -> Redux
	- useDispatch, ... 변경이 감지된 곳만
	- slice 단위로 생성
	- Reducer : state가 어떻게 업데이트 되는지 지정하는 Reducer 함수
