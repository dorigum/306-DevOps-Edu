### SSE 푸시 데이터 형식
SSE는 EventSource가 자동으로 해석할 수 있도록 서버로부터의 푸시되는 데이터의 규칙이 정해져 있음.

- mime 타입은 text/event-stream, charset 파라미터는 필요 없음.
- 문자 인코딩은 UTF-8.
- 줄 바꿈 코드는 `\r\n` `\n` 모두 유효함.
- `:`(콜론)으로 시작하는 줄은 주석.
- 빈 줄이나 파일 끝은 이벤트 구분자가 됨.
- 주석이나 빈 줄 이외는 ‘필드 이름: 필드 값’ 이라는 형식으로 작성.
- 필드 값이 없을 경우 콜론 다음을 생략할 수 있음.
- 가독성을 좋게 하기 위해 콜론과 필드 값 사이에 공백 하나를 포함할 수 있음.
- 개행 문자 두 개(`\n\n` 또는 `\r\n\r\n`)로 메시지의 끝을 표시해야 함


### SSE 응답데이터 형식의 유효한 필드
- 응답 데이터 형식에 있어서 유효한 필드 이름이 또한 정해져 있음

- event
	- 브라우저가 발생시킬 이벤트
	- 기본은 message임

- data
	- 서버가 보낼 메시지
	- 한 번에 여러 개를 보낼 수 있음
	- 값이 없으면 수신측에서 message 이벤트가 발생하지 않음

## Tool Calling
### 왜 Tool Calling(Function Calling)이 필요한가?

![[Pasted image 20260615121844.png]]

- 왼쪽의 Chatbot은 학습된 지식만을 기반으로 답변할 수 있기 때문에 실시간 데이터 조회나 외부 시스템 제어가 어렵다.

- 반면 오른쪽의 AI Agent는 Spring AI의 **Tool Calling** 기능을 통해 데이터베이스 조회, 외부 API 호출, 이메일 전송, 파일 처리와 같은 실제 작업을 수행할 수 있다.

- 즉, AI가 단순히 답변만 하는 수준을 넘어 **외부 시스템과 연결되어 행동(Action)을 수행하는 Agent로 진화하는 핵심 기술이 바로 Tool Calling**이다.

### Tool Calling 흐름

![[Pasted image 20260615123632.png]]

① 모델이 특정 도구를 사용할 수 있도록 하려면, **해당 도구에 대한 정보를 채팅 요청에 포함시켜야 한다.** 각 도구에 대한 정보에는 이름, 설명, 그리고 입력 매개변수의 구조가 포함된다.

② 모델이 특정 툴을 호출하기로 결정하면, 정의된 스키마에 따라 해당 툴의 이름과 입력 매개변수들이 포함된 응답을 보낸다.

③ 이 애플리케이션은 제공된 입력 매개변수를 사용하여 해당 도구를 식별하고 실행하는 역할을 담당한다.

④ 툴의 실행 결과는 애플리케이션에 의해 처리됩니다.

⑤ 이 애플리케이션은 툴 호출의 결과를 모델로 다시 보낸다.

⑥ 이 모델은 툴 호출의 결과를 추가적인 컨텍스트로 활용하여 최종 답변을 생성한다.

![[Pasted image 20260615124016.png]]

이 그림은 Spring AI와 OpenAI GPT가 Tool Calling을 수행하는 전체 흐름을 보여준다.

먼저 Spring AI는 사용할 수 있는 도구의 이름, 설명, JSON 스키마 정보를 GPT에 전달한다.
사용자의 질문을 분석한 GPT는 필요한 도구가 있다고 판단하면 실행할 도구명과 파라미터를 JSON 형태로 반환한다.
Spring AI는 해당 요청을 받아 내부적으로 적절한 Java 메서드에 라우팅하고 실제 비즈니스 로직을 실행한다.
실행 결과는 다시 JSON 형태로 GPT에 전달되며, GPT는 이를 바탕으로 최종 자연어 답변을 생성한다.
즉, GPT는 어떤 도구를 사용할지 결정하고, 실제 실행과 보안 관리는 Spring 애플리케이션이 담당하는 구조이다.
